## 三、核心实现

### 3.1 唯一权威顺序

```
章序：chapters.seq ASC, chapters.id ASC
章内：story_shots.shot_no ASC, story_shots.id ASC
```

`Chapters.list` 只有 `ORDER BY seq ASC`（`chapters.seq` 允许同值），因此本模块**不读 `Chapters.list`**，而是自己写 `ORDER BY`（`listAuthoritativeShots` / `chapterOrder`）。N-EXT5 用"两章 `seq` 改成同值"验证顺序确定且可复现（同 `seq` 退化到 `chapter_id ASC`）。

### 3.2 纯追加 vs 改变顺序（先判定，再选算法）

`isPureAppend(projectId, chapterId, shotNos)` 三个条件全满足才算纯追加：

| # | 条件 | 不满足时 |
|---|---|---|
| ① | 目标章是权威序最后一章 | `reason='NOT_LAST_CHAPTER'` |
| ② | 新镜 `shot_no` 全部大于该章现有最大值 | `reason='NOT_TAIL'` |
| ③ | 该章没有"未提交的镜"（由 `assertChapterSubmitComplete` 保证） | 章级拒写 |

- 纯追加：`appendStoryShots` → 同一事务内 `COALESCE(MAX(global_no),0)+1` 递增，**不调用 `renumberTwoPhase`**，写完再 `assertAppendedLast`（断言它真在权威序末尾）。
- 改变顺序：`applyTargetOrder(projectId, orderedIds)` 先算**完整目标序**，再算**受影响区间**，最后两阶段重编。

### 3.3 两阶段原语（`shot_no` / `global_no` 共用）

| 步 | 动作 | 实现要点 |
|---|---|---|
| 0 | 整体校验 | 每行必须有 `id`、无重复、最终值是 ≥1 整数（避免"写到一半才发现参数错"） |
| 1 | 区间内该列全部写 `-(i+1)` | 腾空旧值：`uq_ss_sn` / `uq_ss_gn` 是即时检查，不腾空就撞索引 |
| 2 | 再写最终正值 | 每行断言 `changes === 1`，找不到镜即 `GLOBAL_ORDER_BROKEN` |
| 3 | 同一事务 + 异常回滚 | 本函数自带 `tx`，被外层 `tx` 包住时自动复用（`tx` 支持嵌套复用，不重复 BEGIN） |

- **R-1**：负值只在事务内出现；`assertGlobalOrder` 检查 `shot_no/global_no < 1` 并兜底。
- **R-2**：`applyTargetOrder` 里两次 `renumberTwoPhase` 在**同一个 `tx`** 内（先 `shot_no`，再 `global_no`）。
- **R-3**：只 `UPDATE story_shots SET <col> = ? WHERE id = ?`，**从不碰 id**。

受影响区间（§4.4.1.3）：

| 字段 | 区间 | 实现 |
|---|---|---|
| `shot_no` | 该章全部镜 | 只要某章有任何一镜号变了，就把**该章全部镜**纳入重编 |
| `global_no` | 第一个排名变化的镜 → 项目最后一镜 | `k` = 目标序与当前序第一个不同位置；`base` = `k-1` 的现号（前置镜一个不动） |

### 3.4 编号自检（N-6 / N-7）

`assertGlobalOrder(projectId)` **按权威序读回**（`JOIN chapters` 取 `seq`），四项全查：

1. 章内 `shot_no` 恰为 `1..n`（排序后逐位比对——重复号会让 `list[i].shot_no !== i+1`）
2. 项目内 `global_no` **严格递增**
3. 无负值 / 非正整数
4. 无重复

任一不满足抛 `GLOBAL_ORDER_BROKEN`，由外层事务整体回滚。**不是只查唯一索引**：N-T6 先证明 `uq_ss_gn` 拦得住，再 `DROP INDEX` 后证明自检仍能发现（这是 V3-B-06 点出的漏洞）。

### 3.5 章级提交限制（§4.4.1.4）

`assertChapterSubmitComplete({ projectId, chapterId, submitted })`：

| 形态 | 判定 | 结果 |
|---|---|---|
| 提交本章全部镜 | `missing.length === 0` | `mode='full'` 或 `'in_place'` |
| 尾部追加 | 新增号全部 > 本章现值且无缺号 | `mode='append'` |
| 就地更新（号没变、无新增） | 允许部分提交 | `mode='in_place'` |
| 中间插入 / 带 id 的调换，但本章有镜未提交 | — | `CHAPTER_SUBMIT_INCOMPLETE`（C3，**0 行写入**，四要素：`chapter_id` / `field='shots[]'` / `expected` / `actual` + `missing_shots[]`） |
| 同批重复 `shot_no` | — | `SHOT_NO_DUPLICATED`（C3，`scope='chapter'`、`level='fail'`） |

### 3.6 资产契约（AS-1~AS-10）

`resolveShotAssets`（纯解析，不落库） → `writeShotAssets`（整组替换 + 派生回填，自带事务） → `writeStoryShotWithAssets`（插镜 + 写资产同事务）。

| 规则 | 落点 |
|---|---|
| AS-1 名称精确匹配 | `WHERE project_id = ? AND category = ? AND TRIM(name) = ?`；0 命中 `ASSET_NOT_FOUND`，≥2 `ASSET_NAME_AMBIGUOUS`（返回候选 id） |
| AS-2 项目归属 | 传 `asset_id` 时比对 `assets.project_id`，不符 `ASSET_NOT_IN_PROJECT` |
| AS-3 类别一致 | `asset.category !== role` → `ASSET_ROLE_MISMATCH` |
| AS-4 role 值域 | 先判值域（连查库都不查）：`music`/`sfx`/`video`/`other` → `ASSET_ROLE_INVALID` |
| AS-5 order_no | 同 role 内按传入顺序 1..n；显式给的号与推算值不一致 → `ASSET_ORDER_GAP`；写入是**整组替换**（先 `DELETE` 后 `INSERT`） |
| AS-6 voice ≤ 3 | 计数先于排号，第 4 条 `VOICE_OVERFLOW`（DDL 的 `CHECK` 兜底） |
| AS-7 variant_of | 仅 `costume`/`age` 且 `assets.parent_id` 非空时写父 id；父不在本项目 `ASSET_VARIANT_ORPHAN`；其他情况强制 `''` |
| AS-8 场景一致 | `role='scene'` 的 `asset_id` 必须等于 `scene_states.scene_id`；虚拟场次两侧都空跳过；否则 `SCENE_ASSET_MISMATCH` |
| AS-9 voice_ids 派生 | `UPDATE story_shots SET voice_ids = JSON(role='voice' ORDER BY order_no)`；外部传入被忽略并留痕 `DERIVED_FIELD_IGNORED` |
| AS-10 同事务 | `writeStoryShotWithAssets` 一个 `tx`；资产校验失败 → 镜与关联一起回滚 |

**与旧路径的关键差异**：旧 `set_storyboard` 的 `idsOf()` 命中不到资产名时只回报、照常写入。本实现一律 `ASSET_NOT_FOUND` 直接拒绝（N 条用例里 AS-1c 专门钉这条）。
