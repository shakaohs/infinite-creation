## 一、实施摘要

本阶段做完六件事，全部围绕"进入阶段 2 之前必须具备的结构能力"：

1. **21 张新表 + 25 个索引**：3 ops + 1 archive + 14 biz + 3 d02_ext，按 D02-03 V3 §11.1 的顺序建，全部 `IF NOT EXISTS`，表齐后统一建索引。
2. **既有两表兼容**：`projects` 加 `structured_spec`（新库走 DDL、历史库走 `ensureColumn`，两条路径都能得到同一列）；`shots.blocking` 阶段 0 已完成，本阶段只读不写。
3. **Manifest 生成器 + 校验器**：从冻结 DDL 文本解析（不读数据库反推），支持 `fresh` / `historical` 两个 profile。
4. **三种 Hash + 规范化序列化**：`cmpStr` / `canonicalStringify` / `sourceSpecHash` / `adaptationHash` / `compiledHash`，纯函数、不读库、禁 `localeCompare`。
5. **迁移登记模型**：三张运维表的状态机与数据访问，四终态无出边、指纹写后不可改、依赖读取 LEFT JOIN。
6. **三张扩展表 + changelog 改造 + 项目删除重排**：选片审计接入现有框架（改造四处），Job 物理删除前归档，`Projects.remove` 按 18 步顺序清理。

## 六、Hash 49 条测试结果

**口径说明**：D01-06 §4.6 的表格是 R-01~R-38 + R-40~R-49（48 条），R-39 被明确写成"负向，代码评审项"。本轮把 R-39 也写成可执行断言（payload 里不得出现 `track` / `fragments` / 下划线键），凑足 **49 条**。

| 结果 | 数量 | 说明 |
|---|---:|---|
| 通过 | **43** | R-01~R-35、R-38、R-39~R-44、R-46 |
| 显式 skip | **6** | R-36、R-37、R-45、R-47、R-48、R-49 |
| 合计 | **49** | 另有 2 条额外用例（`canonicalStringify` 十种顺序、`cmpStr` 三语言），共 51 个 test |

**6 条 skip 的共同原因**（不是"没写"，是"本阶段没有被测对象"）：它们验证 `pickLegalCut` / `assertAttribution` / `planAdaptation` / 切点量化边界，属 **阶段 4 适配层**。任务书 §九 明确"不得在阶段 1 提前实现 Seedance/H3 适配算法"。skip 在测试输出里显式可见，不计入通过。

**关键通过项**：
- R-25 同源证明：同一分镜两套 track → `sourceSpecHash` 逐字相同、`adaptationHash` 与 `compiledHash` 均不同
- R-26 五项全序：动作按正序/逆序/随机输入 → source 不变
- R-32/R-33 引用映射：被引用的动作换 id 并同步更新引用 → source 不变；只改引用目标内容 → 变
- R-42 跨 locale：`LANG=en_US / tr_TR / sv_SE` 三种环境起独立进程跑同一 fixture → 逐字相同
- R-44 `posRel` 13 行矩阵逐行核对，含 `not_applicable` 先于缺失检查、显式 `known` 不能翻案、`legacy` 一律 unknown
- R-46 静态检查：`lib/core/hash/` 内 `localeCompare` 零命中、无裸 `stripRef(` 调用（先剥注释再检查，避免把说明文字判成违规）

**一个必须写明的边界**：`canonState` 只做"undefined→null + 递归规范化"，**不补齐 D01-02 的完整字段表**——那需要一张阶段 1 未引入的字段清单。所以"缺字段补 null"只对输入里出现的键生效。这一点登记为 R-12（C 级）。
