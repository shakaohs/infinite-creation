## 二、D51-01：U-36-2 审计策略最终影响分析

### 2.1 `segment_id` 的完整生命周期路径【源码】

| 阶段 | 写入点 | 是否产生审计 | 说明 |
|---|---|---|---|
| 创建 | `insertStoryShot`（`global-order.js:254`） | **是**（A2 create） | `segment_id` 通常为 `''`；`meta.segment_id` 另存一份 |
| 投影分配 | `project-units.js:199` **直写 SQL** | **否** | 仅在值变化时写；这是 U-36-2 的争议点 |
| 业务更新 | `updateStoryShot`（允许列含 `segment_id`） | 是（A2 update） | **当前无调用方传该列**（两处调用只传内容字段） |
| 删除 | `deleteStoryShot` | 是（A2 delete，`before` 含 `segment_id`） | 行消失后历史归属只存于日志 |
| 段删除 | 投影 0 镜段专用 `DELETE FROM shots` | 否（A6 要求） | 不动 `story_shots` 行 |
| 章删除 | `Chapters.remove` | 否（**未级联**） | 见 §八 F3 |
| 项目删除 | `Projects.remove` 级联 | 否 | `story_shots` 随项目清空 |
| 回滚 | `rollbackLogs` → 整行复原 | 是（rollback 日志） | **会按 `before` 快照连 `segment_id` 一起复原**，见 §2.4 |

### 2.2 方案 A：`segment_id` 纳入 `VOLATILE.story_shot`

| D51-01 必答项 | 结论 |
|---|---|
| 失去哪些审计追溯能力 | 失去「某镜曾经属于哪个段」的**直接**历史。可以从「当前段 + 投影输入 + 段 id 派生规则」重算**当前**归属，但**无法还原历史归属** |
| 是否影响 A2 五实体审计完整性 | **不影响**。A2 的五个实体仍在；`story_shots` 的 create/delete 审计与 A 组成分更新审计照旧。被豁免的只有"投影派生指针"这一个字段 |
| 是否与 D02-40 冻结条款冲突 | **不冲突，但需要授权**。§6.2 的 A2 行 `VOLATILE = updated_at, voice_ids` 是冻结矩阵；加入 `segment_id` 属于修改该矩阵，D02-40 §4.2 注（U-36-2）明确"不由本任务书单方面决定" |
| 是否需要额外审计机制弥补 | 建议补**非审计轨迹**（不算审计）：`projectSceneUnits` 返回的 `segmentWrites`（已存在），由调用方记录到任务输出。**不建议**为此新建表（需 DDL） |
| 对 A6 零增量的影响 | **无关**。A6 约束 `shots` 表；`segment_id` 属 `story_shots`。选 A 反而让"投影不产内容日志"的语义更干净 |

### 2.3 方案 B：保留（恢复）`segment_id` 的常规审计

| D51-01 必答项 | 结论 |
|---|---|
| 哪些投影行为会产生审计 | 仅"`segment_id` 值真的变化"的那一次写：首投（每镜 1 条）、段重建/合并/拆分导致的重新归属（每次 1 条/镜） |
| 哪些是真实业务变化、哪些是派生指针 | **全部是派生指针变化**。投影不是用户在改内容，是系统按 Stage 3 重算归属 |
| 是否会造成 A6 零增量失败 | **不会**。A6 管 `shots`。真正受影响的是 A2 日志的可读性：`change_logs` 里会混入大量"系统重新归属"记录 |
| 能否在不改冻结语义下做到幂等投影 | **能**。现有"仅值变化才写"已经把重复投影的日志量压到 0；首投与非幂等结构变化的日志是**有界**的（O(镜数)） |
| 对审计噪声/回滚/历史追溯的影响 | 噪声：中（首投 N 条，之后按变化量）；回滚：**危险** —— 见 2.4；历史追溯：完整 |

### 2.4 关键发现：方案 B 的安全前提是 H-13，而 H-13 未实现【运行】

探针（`D02-51-probes-h08-h09-h13.txt` 第 5 段）实测：

```
投影前对 story_shots 做一次 updateStoryShot(visual_content)   → A2 update 日志 before.segment_id = ''
投影把 segment_id 写成 seg_66a47a59…                          → 行已是新归属
rollbackLogs({ logId: 那条 update, force: true })              → applied = 1
回滚后 segment_id = ''，视觉内容回到旧值；段行仍在（孤儿段 1 行）
```

也就是说：**只要 A2 update 日志存在（今天就有），回滚就会按整行快照把 `segment_id` 一起打回旧值**，而 `shots` 段行不会跟着变 —— 镜与段脱钩。

D02-40 H-13 写的是「结构化项目回滚 → **409**」。实测该分支**不存在**：

| 场景 | 实测结果 |
|---|---|
| 结构化项目，投影后回滚一条 story_shot create | `blocked=true, applied=0`（**漂移保护**偶然挡住，不是结构化拒绝） |
| 结构化项目，**未投影**时回滚 create | `applied=1`，镜被删除，段行残留 |
| 结构化项目，投影后 `force=true` 回滚 | `applied=1`，镜被删除 |

结论：**H-13 未实现**；方案 B 只在 H-13 落地后才安全（否则每条投影日志都成了"可以把段指针打回去"的入口）。

### 2.5 推荐、证据链、风险、兼容性

| 项 | 结论 |
|---|---|
| **推荐** | **方案 A**：把 `segment_id` 加入 `VOLATILE.story_shot`（仍**不**改投影的"仅值变化才写"） |
| 理由 | ① 它是投影派生的归属指针，不是创作内容；② 记进 A2 会让"内容变更史"失真；③ A 天然不产生可回滚的投影日志，减少 2.4 那类脱钩面；④ A6 无关，不会被破坏 |
| 代价 | 历史归属不可直接查证；只能由当前状态 + 派生规则重算当前值 |
| 风险 | 低。`segment_id` 不进任何指纹（`seg-2`／`qcdep-2`／`solverInputHash` 都不含），不影响求解与 QC |
| 兼容性 | 变更只影响"是否写一条日志"，不改表、不改读写接口、不改投影结果 |
| 是否需要用户批准 | **是**（改 §6.2 冻结矩阵，可能触发决策升版） |
| 是否需要新增架构决策 | **是**（建议编号 AD-51-01，替代 D02-49 的 AD-48-01） |
| 本轮是否实施 | **否**。`changelog.js` 与投影审计方式保持 `5011a81` 原样 |

> 补充：无论选 A 还是 B，**H-13 都必须先落地**。A 降低风险面，但不能替代 H-13（A 之前产生的 A2 日志、以及未来任何 `updateStoryShot` 日志仍可被回滚打回指针）。
