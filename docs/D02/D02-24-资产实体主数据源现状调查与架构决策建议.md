# D02-24 · 资产实体主数据源现状调查与架构决策建议

> 任务性质：调查与决策建议，**不含实施**。
> 本轮**未修改任何业务代码、DDL、Schema Manifest，未操作真实数据库，未启动 P10**。
> 结论标记：**【事实】**＝源码／隔离库实跑可复现；**【推断】**＝由事实推出但有前提；**【待确认】**＝需要用户裁决。

## 一、结论先行

### 1.1 选 A：**已有正式资产实体数据源，可以复用**

```
A. 已有资产实体来源，可以复用。
```

资产实体主数据源是 **`assets` 表**（26 列，主键 `id`，`project_id` 归属，含 `name` / `category` / `parent_id`），
配一套完整 CRUD（`lib/core/db.js` 的 `Assets`：`list` / `get` / `create` / `update` / `remove` / `usageOf` / `listWorks`），
由素材库界面（`app/pages/AssetsTab.jsx`）、9 条 API／Agent 入口、剧本抽取与分镜导入共用。
`shot_assets.asset_id` 引用的就是 `assets.id` —— 有代码级强校验（存在性、项目归属、`category == role`）。
**不需要新建资产实体表，不需要任何 DDL。**

### 1.2 必须同时说的两件事（否则"A 可复用"会被误读成"已经接好了"）

**① D02-23 §R2-3 的"情况 B（无实体表）"是调查范围错误，本报告予以纠正。**

D02-23 只核了 `lib/core/schema/tables.js`（阶段3 新建表）与 `lib/core/schema-manifest.json`（21 表登记），
而 `assets` 是**阶段1 基线表**，建表语句在 `lib/core/db.js:130`（`initSchema()` 里的 `CREATE TABLE IF NOT EXISTS assets`），
两者都不在 D02-23 的检索范围内。于是得出"全库 21 表无 assets"——**21 表对，全库错**：隔离库实跑共 **33 张表**，`assets` 在其中。

因此 `assetEntities.wired=false` 的**正确含义不是"没有数据源"，而是"有数据源但没接线"**。
这条区别决定后续成本：补数据源=DDL+迁移；接线=一个函数体。

**② 但接线之后，资产规则依然不会自动变成"已验证"——因为引用侧也还没接通。**

`shot_assets` 的**唯一写入模块** `lib/core/render/shot-assets.js`（`writeShotAssets()` :224）在整个仓库里
**只有测试在调用**（`tests/stage3-p3-shot-assets.test.mjs`），`app/` 与 `lib/` 内零调用方；
生产环境的镜头↔资产绑定仍然写在 **legacy `shots` 表的 `character_ids` / `scene_ids` / `prop_ids` / `costume_ids` / `age_ids` / `audio_ids`** 列上，
由 `Shots.create`(:950) / `Shots.update`(:984) 写入、`lib/core/refs.js:68~86` 消费。
同理，`story_shots` 的唯一写入入口 `insertStoryShot()`（`lib/core/render/global-no.js:198`）也没有生产调用方。

**结论**：资产实体数据源（A）与引用关系数据源（`shot_assets`）是两道独立的门。
本轮回答第一道门：**有，可复用**。第二道门（`shot_assets` 生产接线）属阶段3 接线工作，见 §十一。

| 层 | 方法 | 覆盖 |

任何"不存在"的结论都必须过这一关。

## 三、相关表与字段清单

### 3.1 `assets`（资产实体主数据，26 列）【事实：`PRAGMA table_info` 实跑】

| 列 | 类型／约束 | 与 QC 的关系 |
|---|---|---|
| `id` | TEXT，PK（uuid v4） | **C.4 定位键**，`shot_assets.asset_id` 指向它 |
| `project_id` | TEXT NOT NULL | 项目归属；AS-2 强制同项目 |
| `category` | TEXT NOT NULL | **C.4 纳入**；AS-3 要求等于 `role`；值域 10 项 |
| `name` | TEXT NOT NULL | **C.4 纳入**；AS-1 按名精确匹配 |
| `parent_id` | TEXT，DEFAULT `''` | **C.4 纳入**；语义＝变体父（character），见 §3.5 |
| `description` | TEXT | 排除（AR-5：无规则读） |
| `prompt` / `prompt_used` / `prompt_locked` / `negative_prompt` | TEXT／INTEGER | 生成用，排除 |
| `image_path` / `audio_path` / `video_path` | TEXT，项目内相对路径 | 文件位置，排除（不是实体语义） |
| `voice_desc` / `voice_desc_used` / `voice_ref` / `lyrics` / `max_duration` | TEXT／REAL | 音色与音乐，排除 |
| `source` / `consistency_key` / `versions` / `params` / `status` / `error` | TEXT／INTEGER | 生成态与版本，排除 |
| `created_at` / `updated_at` | INTEGER | 时间，排除 |

索引：`sqlite_autoindex_assets_1`（主键）、`idx_assets_project`（`project_id`，`db.js:314`）。
**没有** `(project_id, category, name)` 唯一约束 —— 同名资产可以重复存在（§3.5 实测）。

### 3.2 `shot_assets`（镜头↔资产引用，5 列）【事实：`lib/core/schema/tables.js:198`】

| 列 | 约束 | 语义 |
|---|---|---|
| `shot_id` | 复合 PK | 指向 `story_shots.id`（阶段3 镜），**不是** legacy `shots.id` |
| `asset_id` | 复合 PK | 指向 `assets.id` |
| `role` | 复合 PK，值域 6 项 | `character` / `scene` / `prop` / `costume` / `age` / `voice`，必须等于 `assets.category` |
| `order_no` | NOT NULL，`>=1` | 同 `(shot_id, role)` 内从 1 连续；`voice` 上限 3（DB `CHECK`） |
| `variant_of` | TEXT DEFAULT `''` | **`assets.parent_id` 在绑定时刻的快照副本**，非独立关系 |

索引：`idx_sas_asset(asset_id, role)`、唯一约束 `(shot_id, role, asset_id)` 与 `(shot_id, role, order_no)`。
**无外键约束**（全库 `FOREIGN KEY` 命中数 = 0），引用完整性靠应用层。

### 3.3 `reference_images`（参考图上传记录，12 列）【事实：`db.js:291`】

`id` / `project_id` / `chapter_id` / `asset_id`（可空）/ `name` / `image_path` / `mode`（`reference`｜`library`）/ `category` / `description` / `shared` / `origin` / `created_at`。

它是**参考图这一层文件记录**，不是第二个实体库：`mode='library'` 上传时，路由先 `Assets.create()` 建实体、再回填 `reference_images.asset_id`
（`app/api/projects/[id]/references/route.js:118~131`）。`mode='reference'` 时 `asset_id` 为空。
所以"多来源"只发生在**文件层**，实体层唯一。

### 3.4 两套镜头↔资产绑定（并存，需收敛）

| 维度 | legacy `shots`（生产在用） | 阶段3 `shot_assets`（已建，未接线） |
|---|---|---|
| 表 | `shots`（`character_ids` 等 7 个 JSON 列） | `shot_assets`（行式，含 role／order_no） |
| 写入 | `Shots.create`(:950) / `Shots.update`(:984) → `normalizeShotRefs()`(:890) | `writeShotAssets()`（`shot-assets.js:224`） |
| 生产调用方 | 界面 `ShotMaterialPicker` / API `PATCH /shots/:sid` / Agent `set_storyboard` | **无**（仅测试） |
| 读取 | `lib/core/refs.js:68~86`（组装参考图／音色） | `lib/core/continuity/load-scene.js:177`（喂 QC） |
| 语义 | 数组，无 role／顺序 | 行式，role＋order_no＋variant_of |

`story_shots.voice_ids`（`tables.js:124`）是 `shot_assets(role='voice')` 的**派生列**（AS-9），
而 legacy `shots` 没有对应派生列，直接把 id 写进 `audio_ids`。两套模型对"音色"的表达也不同。

### 3.5 `parent_id` 的真实语义【事实：`db.js:752~780` 守卫 + 隔离库实跑】

- `parent_id` **只表示"服装／年龄变体挂在哪个角色下"**，不是任意层级树：
  - `category ∈ {costume, age}` 且 `parent_id` 为空 → `BAD_VARIANT_PARENT`（实测抛错）；
  - `category ∉ {costume, age}` 且带 `parent_id` → `BAD_ASSET_PARENT`；
  - 改分类离开变体族时自动清空 `parent_id`。
- 消费侧印证：`refs.js:74~86` 只按 `parent_id` 把 costume／age 映射到角色，用于替换角色参考图。
- 因此 C.4 里 `parent_id` 的"变体归属"语义**与实现一致**，但**不要**把它当通用父子树使用。

所有入口都过它，因此"分类值域""变体父守卫""变更日志"三件事只在一处实现。

### 4.2 更新

`Assets.update()`（`db.js:782`）是唯一 UPDATE 点，调用方包括：
资产编辑器 `PATCH /assets/:aid`（`.../[aid]/route.js:51`）、素材上传 `.../upload/route.js:53~56`、
图像生成 `.../generate/route.js:36`、音色设计／克隆 `.../design-voice:32` / `.../clone-voice:28`、
音乐／数字人／秩影的状态推进。**每次 create／update／delete 都写 `change_logs`**（`recordChange`），可回滚。

> 对 QC 的意义：`category`／`name`／`parent_id` 的修改**一定**会经过 `Assets.update`，
> 所以"资产实体内容变化 → 依赖 Hash 变化"这条链在上游是可捕获的（下游见 §6 矩阵）。

### 4.3 引用（镜头绑定）

- **生产实际路径**：界面 `ShotMaterialPicker.jsx` → `PATCH /shots/:sid` → `Shots.update` → `normalizeShotRefs()`
  （`db.js:891`）按 `SHOT_REF_FIELD_CATEGORIES`(:873) 过滤"本项目不存在或分类不符"的 id，写入 `shots.*_ids`。
- **阶段3 路径**：`writeShotAssets()`（`shot-assets.js:224`）→ `DELETE` + 逐行 `INSERT INTO shot_assets` + 回填 `story_shots.voice_ids`；
  校验 `ASSET_NOT_FOUND` / `ASSET_NOT_IN_PROJECT` / `ASSET_ROLE_MISMATCH` / `ASSET_NAME_AMBIGUOUS` / `ASSET_VARIANT_ORPHAN` / `SCENE_ASSET_MISMATCH`。
  **全仓无生产调用方**（仅 `lib/core/index.js:70` 再导出 + 测试）。

### 4.4 删除

| 行为 | 位置 | 现状 |
|---|---|---|
| 删资产 | `Assets.remove()`（`db.js:837`） | 事务内**级联删子变体**（`parent_id` 指向它的行），用 `seen` 防环形；写变更日志 |
| 是否清理 `shot_assets` | — | **不清理**（全仓 `DELETE FROM shot_assets` 只在 `writeShotAssets` 内的整组替换） |
| 是否清理 legacy `shots.*_ids` | — | **不清理**；`normalizeShotRefs` 只在"下次写这一镜"时丢弃悬空 id（注释已承认"删除素材就会造出悬空 id，且永远删不掉"） |
| 删除前的影响提示 | `Assets.usageOf()`（`db.js:822`） | `children` 正确；`shotIds` **只扫 legacy `shots`**，不扫 `shot_assets`/`story_shots` |
| 删项目 | `Projects.remove`（`db.js:697~712`） | 顺序正确：先 `shot_assets` 等镜级从表，再 `assets`，最后 `projects` |

**风险（引用完整性缺口）【事实】**：删资产后，`shot_assets` 里的行会变成悬空引用。
下游行为是 fail-closed 的（依赖层用 `__missing__` 哨兵，V-03 判 `fail/ASSET_ROLE_MISMATCH`），
不会静默放行；但"悬空行"本身是数据债，且 `usageOf` 的删除前提示**看不见**阶段3 引用，用户会在不知情下删掉正被 `story_shots` 引用的资产。

### 4.5 实体与文件的关系

- 实体在 `assets` 行，文件在项目目录：`image_path` / `audio_path` / `video_path` 均为**项目内相对路径**，
  由 `resolveProjectPath()`（`refs.js:17`）解析并做越界防护（拒绝 `..`、绝对路径）。
- 一个实体可以有多个文件（图／音／视频各一）＋ `versions TEXT DEFAULT '[]'`（历史版本数组）。
- 文件丢失时：`refs.js:107` 判 `!fs.existsSync` → 该参考图被跳过；全无图时抛"还没有任何参考图"。
  **文件不是实体真相**：实体行在、图不在是常态（刚建完还没出图），所以不能把文件目录当实体源（§七 方案 C 否决理由）。

## 五、`shot_assets.asset_id` 到底引用了什么

**答：引用 `assets.id`，即"项目内的资产实体主键"（uuid v4，36 字符）。不是文件路径、不是业务名称、不是模块自造标识。**

代码证据（`lib/core/render/shot-assets.js:106~152`）：

```js
if (assetId) {
  asset = db.prepare('SELECT * FROM assets WHERE id = ?').get(assetId);          // :118
  if (!asset) throw ...('ASSET_NOT_FOUND');
  if (asset.project_id !== projectId) throw ...('ASSET_NOT_IN_PROJECT');          // :121~125
  if (asset.category !== role) throw ...('ASSET_ROLE_MISMATCH');                  // :127~131
} else {
  // AS-1：按 (project_id, category, name) 精确匹配，重名则要求改传 id
}
```

| 问题 | 答案 | 证据 |
|---|---|---|
| 是全局资产 ID 还是项目内？ | **全局唯一 uuid，但语义上项目内使用**：`Assets.create` 用 `uid()` 生成；跨项目引用被 AS-2 拒绝 | `db.js:753`、`shot-assets.js:121` |
| 会不会跨项目复用同一 id？ | 不会（同 id 只有一行，`project_id` 固定）；但**同一资产可被同项目任意多镜引用**（`shot_assets` 复合 PK 允许） | DDL |
| 能否用业务名称代替？ | 能，但**仅作为输入形态**（`characters: ['李雷']`）；落库仍是 id。重名时抛 `ASSET_NAME_AMBIGUOUS` | `shot-assets.js:132~149` |
| `variant_of` 是什么？ | `assets.parent_id` 的快照（`resolveVariantOf` 返回父 id） | `shot-assets.js:171~181` |
| 名称唯一吗？ | **不唯一**（无唯一约束，实测同名可建两条） | `PRAGMA index_list(assets)` |
| id 稳定性 | 建行时生成后不变；`Assets.update` 不改 `id` | `db.js:811`（UPDATE 不含 id） |

## 七、三种架构方案对比

### 方案 A：复用 `assets` 表（推荐）

| 项 | 内容 |
|---|---|
| 数据源 | `assets`（`db.js:130`） |
| 读取方式 | `SELECT id, name, category, parent_id FROM assets WHERE project_id = ? AND id IN (本镜引用的 asset_id...)` |
| 与 `shot_assets.asset_id` 对应 | 直接对应，无需适配层（同一 `id` 空间） |
| 是否满足 C.4 字段 | 全部满足（§6 第 1~4 行） |
| 跨项目泄漏／歧义 | 无：`project_id` 过滤 + AS-2 已在校验层拦过；`id` 全局唯一 |
| 改动量 | **1 个函数体**（`loadShotAssetEntities()`）＋ 1 处调用传参，**0 条 DDL** |
| 成本 | 每场 1 次 `IN` 查询（主键点查，≤ 本场引用 id 数），或每镜 1 次（≤ 7~9 个 id） |
| 风险 | 接线后引用镜头的资产类规则 Hash 会变（哨兵→真值），历史报告自然失效（预期，见 §十） |

### 方案 B：新增正式资产实体表

**前提不成立**：A 已满足 C.4 全部字段与语义，无需新表。若仍要建，等于**同一实体两处存放**，必然出现
"素材库改的 category 与 QC 读的 category 不一致"，违反 SIG-1 的"一套口径"原则。
仅在一种情况下值得考虑：把 `assets` 里的**作品类**行（`video`/`music`/`sfx` 产物）与**素材类**行拆表——
但那是"资产表职责过载"问题，与 C.4 的实体源无关，且需 DDL 与数据迁移，本轮不建议。

> 保留此节是为了留证据链：**曾评估、结论是不做**，而不是漏做。

### 方案 C：用文件元数据／`reference_images`／外部资产库适配

| 维度 | 评估 |
|---|---|
| 数据一致性 | 不成立：文件是产物，实体先行（新建资产常无图）。`refs.js:91~100` 明确"刚建完占位必然无图" |
| ID 稳定性 | 文件路径含 `slugify(name) + uid().slice(0,8)`，改名／重传就变；`assets.id` 才是稳定键 |
| 查询性能 | 目录扫描 + mtime 推断，比一次 `IN` 查询更慢且不可索引 |
| 离线可用 | `resolveProjectPath` 已是本地路径，但文件可被用户手动删／移，实体行不会跟着变 |
| 文件丢失／元数据缺失 | 现有行为是"跳过该参考图"，若用它当实体源，QC 会把"文件丢了"当成"资产类别变了" |
| 与本地自动化匹配 | 不匹配：QC 要的是**确定值**（category/name/parent_id），文件系统给不出 |

**否决**。`reference_images` 亦不能承担：`asset_id` 可空、`category` 只是上传时的分类副本、`mode='reference'` 的行根本没有实体。

## 八、推荐方案与最小接线改动（**待授权，本轮不实施**）

**推荐 A**。实施时的最小改动只有一处（给出草案是为了让决策可评估，不是已改）：

```js
// lib/core/continuity/run-scene.js（当前 :105）
export function loadShotAssetEntities() { return []; }

// 建议改成（签名由调用点给本镜的 shotAssets + projectId）：
export function loadShotAssetEntities({ projectId, shotAssets = [] }) {
  const ids = [...new Set(shotAssets.map((r) => String(r?.asset_id ?? '')).filter(Boolean))].sort(cmpStr);
  if (!ids.length) return [];                       // 本镜无引用 ⇒ 空数组（≠ undefined，QH-16）
  return getDb().prepare(
    `SELECT id, name, category, parent_id FROM assets WHERE project_id = ? AND id IN (${ids.map(() => '?').join(',')})`,
  ).all(String(projectId), ...ids);
}
```

要点（都是前面踩过的坑）：

1. **只 SELECT 4 列**：`description` 等不进 Hash（AR-5），也顺手避免把文件路径带进依赖上下文。
2. **只取本镜子集**：`ctx.assets` 必须是本镜引用子集（SIG-2／AR-7）；依赖层会再过滤一次，但调用方不该传全表。
3. **`[]` 与 `undefined` 可区分**：无引用传 `[]`；`buildQcDependencyContext` 对 `undefined` 直接抛 `QC_DEPS_ASSETS_UNDEFINED`。
4. **同步查询即可**：`run-scene` 全程在同步 `tx()` 内，`getDb()` 是同步驱动，不引入异步。
5. **不要缓存跨场次**：`assets` 可在两次求解之间被改（素材库随时编辑），缓存会让 Hash 用到旧值。

## 十、数据迁移、历史兼容与回滚风险

| 项 | 结论 |
|---|---|
| 数据迁移 | **不需要**：`assets` 是既有表，存量行即刻可用；`id` 不变 |
| 历史引用兼容 | legacy `shots.*_ids` 与 `shot_assets` 并存期，QC 只读 `shot_assets`；接线后 QC 对"只在 legacy 里绑过"的镜头仍然看不到引用（不是本次改动引入，是引用侧未接，§1.2②） |
| Hash 变化范围 | 仅在"本镜有 `shot_assets` 行"时：`name` / `category` / `parent_id` 从 `__missing__` 变为真值 ⇒ 该镜的 `rule_dependency_hash`（V-03／A-07／S-02）与 `qc_dependency_hash` 改变 ⇒ 新报告行插入、旧报告保留为历史（`saveReport` 只与最新一份比） |
| 这是回归吗 | **不是**。哨兵值是"没有实体数据"的占位，不是事实；换成真值是修复。但必须预期到：接线当次所有含引用的镜头会各多一份报告 |
| 回滚 | 单函数回滚（改回 `return []`）即可；已写入的状态行不受影响，报告历史不删 |
| 真实库风险 | 本轮 0 操作；实施时也只需读 `assets`，不写 |
