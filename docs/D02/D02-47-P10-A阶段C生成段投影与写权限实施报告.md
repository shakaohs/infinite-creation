## 四、投影幂等性与段/镜映射证据

### 4.1 幂等

| 判据 | 证据 |
|---|---|
| 重复投影不新建段 | `C01-05`：第二次 `created=0`、`updated=0`、`unchanged=2` |
| 不产生内容日志 | `C01-05`：`listChanges` 总数前后相等（投影**不调** `recordChange`） |
| 不破坏候选 | `C01-07`：挂候选的段被拒删，`shot_videos` 行仍在 |
| 段 id 稳定 | 由 `sha256(project:chapter:scene:idx)` 前 32 位派生 |

### 4.2 镜 → 段映射

| 场景 | 证据 |
|---|---|
| 一镜一段 | `C01-01`：3 镜 ⇒ 3 段，`idx=[1,2,3]` |
| 一段多镜 | `C01-02`：显式 `units` ⇒ 1 段，时长相加、视觉逐行拼接 |
| `segment_id` 回写 | `C01-04`：每镜指向自己那段，两镜不同段 |
| 排序稳定 | `C01-03`：乱序插入（3→1→2）后仍按 `global_no` 排 |
| 整段重投影 | `C05-04`：改镜后段行视觉同步变化 |

### 4.3 一处必须登记的实现缺陷（本轮自己踩到）

**第一版段 id 用 `base64(...).slice(0,40)`** —— 三个段塌成一段（base64 前缀相同、`idx` 在末尾被截掉），投影看起来"成功"却只建了一行。`C01-01` 当场红（`created=1` 而不是 3）。改成定长 `sha256` 摘要后修复。

**这条值得写进报告**：投影的幂等键如果用"截断字符串"，会以"少建了"的形式失败，而不会报错。

## 八、A4 / A5 在投影侧的实际数据流（按 D02-46 §八 纪律记录，不补空调）

阶段 C 的投影只消费 `shot_assets`：段的六组 `*_ids` 来自资产引用行。**站位与动作在投影侧没有写入职责**——它们既不参与段行的 A 组字段，也不被投影读取。

实际数据流（源码核查结论）：

| 实体 | 谁在写 | 谁在读 | 归属阶段 |
|---|---|---|---|
| `shot_blockings` | 目前**无人写**（`writeShotBlockings` 零调用） | 求解器（`solve-continuity` 读站位做首镜基线） | **E**（求解侧） |
| `shot_actions` | 目前**无人写** | 求解器（动作轴输入） | **E**（求解侧） |

因此按冻结契约，A4/A5 的接线责任落在**阶段 E**，本阶段未接，且**没有**为了让表格变绿而补空调用。若阶段 E 核查后发现求解器改为读别的来源，则须在 E 的报告里记录实际数据流与责任归属。
