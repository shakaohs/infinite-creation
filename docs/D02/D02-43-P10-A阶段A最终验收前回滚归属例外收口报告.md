## 二、问题：例外没有动作前提

D42-01 引入的 `requiredProjectIdOf` 第一支原文：

```js
if (!before && !after) {
  if (!explicit) { throw ... }
  return explicit;        // ← 只看了"有没有 projectId"，没看"这是不是回滚"
}
```

为什么这会漏，取决于**哪些动作能走到这一支**：

| 动作 | 调用点是否有更早的拦截 | 能否走到「两侧都空」这一支 |
|---|---|---|
| `create`（A 类） | 有：缺 `after` → `AUDIT_SNAPSHOT_UNREADABLE` | 不能 |
| `update`（A 类） | 有：缺 `before` → `AUDIT_SNAPSHOT_UNREADABLE` | 不能 |
| `delete`（A 类） | 有：缺 `before` → 同上 | 不能 |
| `rollback` | 无（before/after 由回滚动作自己给出） | **能，且这是唯一合法的** |
| **其它任何动作名**（自定义批次名、`import`、`restore` 等） | **没有** | **能 —— 就是这里漏的** |

也就是说：`create/update/delete` 由快照铁律挡住了，`rollback` 是合法例外，
**中间那一类「未在快照铁律里枚举的动作名」既不被挡、也不该被放行**。
上一版对它们一视同仁地返回了调用方传入的 projectId —— 等于留了一条「换个动作名就能绕过归属检查」的路。

## 三、修改内容（唯一一处）

文件 `lib/core/changelog.js`，函数 `requiredProjectIdOf()`（`changelog.js:219`）：

```js
if (!before && !after) {
  // 例外只认回滚（D02-43 收口）
  if (action !== 'rollback') {
    throw auditError('AUDIT_PROJECT_UNRESOLVED',
      `${entity} 的 ${String(action)} 两侧都没有行快照；只有 rollback 允许无快照归属，拒绝用调用方传入的 projectId 兜底`,
      { entity, action, side: 'none', providedProjectId: explicit });
  }
  if (!explicit) {
    throw auditError('AUDIT_PROJECT_UNRESOLVED',
      `${entity} 无行快照且未提供 projectId：拒绝写入无归属的审计日志`,
      { entity, action, side: 'none' });
  }
  return explicit;
}
```

对照任务书八条要求：

| # | 要求 | 落实 |
|---:|---|---|
| 1 | 两侧都为空时，只有 `action === 'rollback'` 才进入例外 | 新增 `action !== 'rollback'` 前置判断 |
| 2 | 非 rollback 一律抛 `AUDIT_PROJECT_UNRESOLVED` | 抛出，且带 `action` 与 `providedProjectId` 便于定位 |
| 3 | rollback 但 projectId 为空仍抛 | 第二条判断保持原样（未改一字） |
| 4 | rollback 且 projectId 有效保持 D42-01 行为 | `return explicit`，用例 D43-01 与 D42-01-G 双向守 |
| 5 | 不改其它 A 类与 B 类实体行为 | 只改「两侧都空」这一支；B 类根本不进入本函数（D43-05 守） |
| 6 | 不新增错误码 | 仍是 `AUDIT_PROJECT_UNRESOLVED` |
| 7 | 不改四个冻结锁接口 | 本轮零触碰 `db.js` 与 `internal/lock-order.js` |
| 8 | 不改 D02-40 / D02-42 / 冻结决策 | `git status` 只有 `changelog.js` 与两个新增文件 |

顺带更新了 `recordChange` 上方那段说明（`projectId` 的适用边界补一句「两侧都无快照时也仅限 `action === 'rollback'`」），
属注释同步，无逻辑变化。
