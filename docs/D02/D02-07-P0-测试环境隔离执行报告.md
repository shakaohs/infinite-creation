## 二、测试入口与数据库调用链

**修前（无入口断言）**

```
npm test
└─ node --test --test-force-exit "tests/*.test.mjs"
   ├─ 各测试文件自行 mkdtemp + 设 IC_DATA_DIR（changelog / stage0 / stage1-* / queue-scheduler）
   │  └─ import lib/core/* → getDb() → [isolated=真] assertEnv + assertDbIsolation(前) → createDb → assertDbIsolation(后)
   └─ tests/unit.test.mjs / agent-gate / srt：**不设 IC_DATA_DIR**
      └─ import lib/core/index.js → 业务函数 → getDb() → [isolated=假] **零检查** → createDb(真路径)
```

**修后（三层，任一不满足即退出码 2、不启动测试、不建库）**

```
npm test
└─ node scripts/test-runner.mjs                      ← ① 入口层（本轮新增）
   ├─ assertEnv()                     IC_DATA_DIR 必须显式 / 绝对 / 非生产 / 非生产子目录 / 可写
   ├─ dbSettings().sqlitePath         取"真正会被打开的文件"（含 config.json 与 IC_DB_SQLITE_PATH 两处覆盖）
   ├─ assertDbIsolation()             按**真实路径**判它是否在 IC_DATA_DIR 内
   └─ spawnSync node --test "tests/*.test.mjs"（env 原样传递）
      └─ 每个测试进程：
         ├─ import lib/core/* → getDb()
         ├─ ② 测试进程层（本轮新增）：NODE_TEST_CONTEXT 存在且无 IC_DATA_DIR → 抛 TEST_REQUIRES_IC_DATA_DIR
         ├─ ③ assertEnv + assertDbIsolation（打开前，原有）
         ├─ createDb
         └─ ④ assertDbIsolation（打开后复核，原有）
```

`NODE_TEST_CONTEXT` 是 Node 自己注入的测试子进程标记（本机实测值 `child-v8`），不依赖项目约定，`node --test tests/xxx.test.mjs` 直接跑也带得上——这是②能覆盖"绕过 ① 直接跑单文件"的原因。

## 三、本轮发现的两个缺口

### A-P0-1（A 级，已修复）：`npm test` 在未设 `IC_DATA_DIR` 时会写真实库

| 项 | 内容 |
|---|---|
| 复现（安全版） | 纯配置探针（不开库）：`sqlitePath = D:\...\data\ic.db`，`source = default:DATA_DIR/ic.db`，`IC_DATA_DIR=(unset)` |
| 复现（行为版） | 无 `IC_DATA_DIR` + 诱饵路径跑 `db-guard-probe.mjs` → `ok:true`、**诱饵库被建出**（证明零检查地打开了库） |
| 复现（真实影响） | `IC_DATA_DIR=<临时>` 单跑 `tests/unit.test.mjs` → 临时目录里出现 `ic.db`(4 KB) + `ic.db-wal`(1.1 MB) + `projects/`。**该文件自己不设 `IC_DATA_DIR`**，故真实运行时会落在 `data/ic.db` |
| 根因 | 两层叠加：`package.json` 的 test 脚本无前置断言；`db.js` 只在"显式设了 `IC_DATA_DIR`"时才判隔离，未设即视为生产模式 |
| 影响 | 与阶段0 那次误写同源：`initSchema` 会 `CREATE TABLE IF NOT EXISTS` + `ensureColumn` 补列，是**写事务**，不是纯读 |
| 修复 | ① `scripts/test-runner.mjs`（入口前置）② `db.js` 测试进程守卫 ③ `package.json` 指向 runner（详见 §9） |

### A-P0-2（低，已收敛）：阶段0 两条历史库用例以只读方式打开真实库

| 项 | 内容 |
|---|---|
| 现象 | `T-08`（VACUUM INTO 取副本核结构）与 `T-09`（指纹比对）都以 `readOnly:true` 打开 `data/ic.db` |
| 实测副作用 | WAL 模式下只读打开仍会刷新 `ic.db-shm` 的 **mtime**：显式开启时 `1795744716 → 1795744798`（09:58:36 → 09:59:58）；**三个文件的内容 SHA-256 全部不变** |
| 判断 | 内容未被写，但"测试运行不得触碰真实库"这条门槛不接受任何形式的写窗口 |
| 修复 | 两条用例默认 `skip`，需 `IC_ALLOW_REAL_DB_READ=1` 显式开启；`REAL_SHA_AT_START` 仍照旧在任何 lib 加载前取（只 `readFile`，不开 SQLite）。显式开启后 stage0 **26/26 全绿** |

## 四、`IC_DATA_DIR` 隔离机制（四层，全部 fail-closed）

| 层 | 判什么 | 实现 |
|---|---|---|
| L1 环境串 | 未设 / 相对路径 / 等于 `<repo>/data` / 位于 `<repo>/data` 之内 / 不可创建 / 不可写（写探针再删） | `assertEnv` |
| L2 真实路径 | `IC_DATA_DIR` 本身是 junction 指向生产目录 → 按 `realpath` 拒（在 mkdir / 写探针**之前**判） | `assertEnv` + `realPathOf` |
| L3 打开前 | `dbSettings().sqlitePath`（**真正会被打开的文件**）按真实路径是否在 `IC_DATA_DIR` 内；库路径指生产目录也拒 | `db.js` ② + `assertDbIsolation` |
| L4 打开后 | 用"此刻的真实路径"再复核一次，失败即 `db.close()` + 抛错 | `db.js` ③ |
| L5 测试进程 | `NODE_TEST_CONTEXT` + 无 `IC_DATA_DIR` → 拒绝（本轮新增，无开关可关） | `db.js` 新增守卫 |

拒绝时**一律抛错终止**，不返回空值、不回退默认库、不"降级继续"。错误码清单：

| 错误码 | 触发 |
|---|---|
| `IC_DATA_DIR_NOT_SET` / `_NOT_ABSOLUTE` / `_IS_DEFAULT` / `_INSIDE_PRODUCTION` / `_SYMLINK_TO_PRODUCTION` / `_NOT_CREATABLE` / `_NOT_WRITABLE` | L1/L2 |
| `DB_PATH_EMPTY` / `IC_DB_PATH_OUTSIDE_DATA_DIR` | L3（含 `IC_DB_SQLITE_PATH` 与 `config.json` 两条覆盖路径） |
| `PATH_RESOLUTION_FAILED` / `PATH_SYMLINK_UNRESOLVED` / `PATH_SYMLINK_LOOP` | 解析器：读不到就证明不了落点 → 拒（只有 `ENOENT`/`ENOTDIR` 才当"不存在"） |
| `IC_DB_PATH_INSIDE_PRODUCTION` | 库路径指回生产数据根 |
| **`TEST_REQUIRES_IC_DATA_DIR`** | **本轮新增**：测试进程未隔离 |
| **`TEST_REQUIRES_SQLITE`** | **本轮新增**：入口不接受 PG（P0 判的是 SQLite 文件路径） |

## 十二、复现命令（供审核方逐条重放）

```bash
# 0) 基线：真库四件套（只读，VACUUM INTO 取副本读结构）
node <evidence>/capture-evidence.mjs "<repo>/data/ic.db" <evidence>/before.json P0-before

# 1) 入口拒绝（无 IC_DATA_DIR）
node scripts/test-runner.mjs --check            # 期望 exit=2, code=IC_DATA_DIR_NOT_SET
npm test                                        # 期望 exit=2, 不启动任何测试进程

# 2) 入口放行（合法隔离目录）
IC_DATA_DIR="$TEMP/ic-test" node scripts/test-runner.mjs --check   # 期望 exit=0 + dbPath 在目录内

# 3) P0 专用用例
IC_DATA_DIR="$TEMP/ic-p0-tests" node --test --test-force-exit tests/p0-isolation.test.mjs

# 4) 全量（默认不触碰真实库）
IC_DATA_DIR="$TEMP/ic-run" npm test             # 期望 453 / 427 pass / 17 fail / 9 skip

# 5) 历史库用例（显式开启）
IC_ALLOW_REAL_DB_READ=1 IC_DATA_DIR="$TEMP/ic-optin" node --test tests/stage0.test.mjs

# 6) 收尾：再取一次四件套与 before.json 对比
node <evidence>/capture-evidence.mjs "<repo>/data/ic.db" <evidence>/after.json P0-after
```
