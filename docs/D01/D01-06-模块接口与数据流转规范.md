## 三、适配层（Split into RenderUnits）

### 3.1 职责

按 TargetProfile 把 Shot 序列切成单元，并生成 N:M 关联。**不属于任何编译器**——否则两编译器会切出不同单元。

### 3.2 接口

```js
/**
 * @returns {{
 *   units: [{ unitNo, track, profileVer, unitDuration, shots: [{shotId, orderNo, tFrom, tTo, splitReason}] }],
 *   warnings: []
 * }}
 */
export function splitIntoUnits({ shots, profile, seamPolicy }) {}
```

### 3.3 切分规则

```
acc = 0
for shot in shots:
   if acc + shot.story_duration > profile.max:
      在当前单元结束前，找最后一个 is_cut_point=1 的镜作为断点
      若无可用剪辑点 → 在最近的「动作 t_to」处劈开当前镜（split_reason='oversize'）
   acc += 截取长度
if 尾单元 < profile.shortFloor:
  并入前单元（若合并 ≤ max）或标 SHORT_UNIT
```

**断点优先级**（`D01-02 §10.1`）：
1. `is_cut_point=1` 的镜后（首选）；
2. 同一镜内的动作 `t_to`（超长镜必须劈时）；
3. **禁止**落在动作中段。

### 3.4 输出落库

- 每个镜进每个单元都写一行 `render_unit_shots`，**即使完整镜**也写（`t_from=0, t_to=story_duration`）；
- 同一镜被多单元引用时，写多行（跨轨道/跨片段）；
- 片段并集必须覆盖 `[0, story_duration]` 且不重叠。

### 4.2 `sourceSpecHash` 必须覆盖什么

V1 只哈希了 6 个字段（`no/size/dir/h/mv/amp/dur/vc/dlg/spk/block/act` 的简化版），**遗漏了**：语气/音效/配乐、道具状态、服装、时间片、`purpose`、`is_insert`、`cam_pos`、`cam_roll_deg`、`lens_mm`、`composition_rule`、`lighting`、参考素材内容。

**V2 定义：凡影响"观众看到/听到什么"的字段，一律纳入。**

```js
function sourceSpecHash({ unit, shots, sceneState, assets }) {
  const payload = {
    specVersion: 2,
    scene: canonical(sceneState, [
      'scene_key','coord_system','fixtures','entries','axis_lock','power_geometry','crowd_switch','time_of_day'
    ]),
    unit: canonical(unit, ['track','profile_ver','unit_duration','seam']),
    shots: shots.map(s => ({
      // —— 标识：只保留影响剪辑顺序的，排除 id ——
      no: s.global_no, shotNo: s.shot_no, sceneKey: s.scene_key,
      // —— 剧作意图 ——
      purpose: s.purpose, dramaticValue: s.dramatic_value, infoDelta: s.info_delta,
      dialogueFunction: s.dialogue_function, isInsert: !!s.is_insert,
      // —— 画面 ——
      visual: s.visual_content, composition: s.composition, lighting: s.lighting,
      // —— 摄影（全部纳入，含机位坐标）——
      size: s.shot_size, dir: s.cam_direction, height: s.cam_height, roll: num(s.cam_roll_deg),
      camPos: s.cam_pos, camTarget: s.cam_target, camDist: num(s.cam_distance_m),
      lens: s.lens_mm, fov: num(s.fov_deg),
      movement: s.movement, amp: s.movement_amp, camPath: s.cam_path,
      compRule: s.composition_rule, camNote: s.cam_note,
      // —— 声音（全部）——
      dialogue: s.dialogue, speakers: s.speakers, narration: s.narration,
      sfx: s.sfx, musicCue: s.music_cue, voiceIds: sorted(s.voice_ids),
      // —— 时间 ——
      duration: num(s.story_duration), slices: s.time_slices,
      ramp: s.speed_ramp, cut: !!s.is_cut_point, timeJump: !!s.time_jump,
      // —— 空间（逐人，按 character_id 排序）——
      blockings: (s.blockings || [])
        .map(b => ({ char: b.character_id, pos: b.position_abs, xy: [num(b.norm_x), num(b.norm_y), num(b.norm_z)],
                     track: b.position_track, anchor: b.anchor_object, behind: b.behind_object,
                     facing: b.facing, gaze: b.gaze_target, posture: b.posture,
                     dist: num(b.distance_to_camera), occ: b.occlusion,
                     hand: b.hand_state, task: b.current_task, inFrame: !!b.in_frame,
                     power: b.power_level }))
        .sort((a, b) => a.char.localeCompare(b.char)),
      // —— 动作（按 t_from + actor 排序，全部 20 字段）——
      actions: (s.actions || [])
        .map(a => ({ actor: a.actor_id, type: a.action_type, primary: !!a.is_primary, tier: a.tier,
                     init: a.init_state, trigger: a.trigger_json, path: a.path_json, force: a.force_json,
                     speed: a.speed_json, power: a.power, cog: a.cog, parts: a.body_parts,
                     contact: a.contact_json, result: a.result_json, follow: a.follow_through,
                     recovery: a.recovery, end: a.end_state, sync: a.sync_json,
                     tFrom: num(a.t_from), tTo: num(a.t_to) }))
        .sort((a, b) => (a.tFrom - b.tFrom) || String(a.actor).localeCompare(String(b.actor))),
      // —— 状态（首尾，影响编译时的"承接上镜"表述）——
      stateIn: s.state_in || null, stateOut: s.state_out || null,
      // —— 资产引用 + 内容指纹 ——
      assets: (s.assets || [])
        .map(x => ({ id: x.asset_id, role: x.role, order: x.order_no, variant: x.variant_of,
                     fp: assets[x.asset_id]?.fingerprint || '' }))
        .sort((a, b) => a.role.localeCompare(b.role) || a.id.localeCompare(b.id))
    })),
    // —— 单元片段范围（同批镜不同切法 → 编译结果不同，必须纳入）——
    fragments: (unit.fragments || [])
      .map(f => ({ shot: f.shot_id, tFrom: num(f.t_from), tTo: num(f.t_to) }))
      .sort((a, b) => a.tFrom - b.tFrom || String(a.shot).localeCompare(String(b.shot)))
  };
  return 'sha256:' + sha256(canonicalStringify(payload));
}
```

### 4.3 规范化序列化规则（稳定性前提）

| 规则 | 实现 | 原因 |
|---|---|---|
| 键排序 | 所有对象键按 UTF-16 字典序输出 | 数据库返回的键序不稳定 |
| 数字 | 整数去小数（`4.0` → `4`），浮点保留 6 位（`(x).toFixed(6)` 去掉尾零） | `4` 与 `4.0` 必须同 hash |
| `null` / `undefined` | 统一为 `null`，且**保留该键**（不省略） | 省略与 `null` 语义不同 |
| 空集合 | `[]` / `{}` 保留，不省略 | 同上 |
| 字符串 | NFC 归一化 + 去首尾空白 | 全角/半角、组合字符 |
| 数组 | **有语义顺序的保持原序**（`time_slices`、`cam_path`），**无序的排序**（`blockings` 按 char、`actions` 按 t_from+actor、`assets` 按 role+id、`voice_ids` 字符串排序） | 插入顺序不应影响 hash |
| 排除字段 | `id`、`created_at`、`updated_at`、`qc_status`、`fill_confidence`、`spec_source`、`unit.id` | 非语义 |

**`num()`**：`null` → `null`；`0` → `0`；`4.0` → `4`；`4.500000` → `4.5`。
**`sorted()`**：字符串数组去重 + 排序。

### 4.4 参考素材指纹

`assets[asset_id].fingerprint` 的计算：

```
fingerprint = sha256(
    asset_id + '|' + category + '|' + name + '|' +
    canonicalStringify(versions || {}) + '|' +
    canonicalStringify(params || {}) + '|' +
    (主图文件 sha256（若可读）)
)
```

**【未核实/限制】**：现有 `assets` 表没有内容哈希列；主图文件路径散在 `versions` JSON 里，格式未统一。**落地时若无法稳定取到文件，`fingerprint` 退化为 `versions+params` 的 hash**，并在 `prompt_packages.ref_pack` 里标注 `fp_level: 'meta' | 'content'`。

**这是诚实标注，不是设计缺陷**：宁可标明"只到元数据级指纹"，也不要假装"素材内容已锁定"。

### 4.6 `compiledHash`

```
compiledHash = sha256(sourceSpecHash + '|' + compilationVer + '|' + profileVer)
```

用途：产物幂等（同输入同编译器 → 同 hash → 不重复插入）；**不等于**同源证明——同源证明只看 `sourceSpecHash`。

| 单元视图 | `render_units` + `render_unit_shots` | ❌ 只读（触发重切） |
| 编译预览 | `prompt_packages` 多版本 | ❌ 只读（触发重编译） |
| 时间线 | `timelines` | 拖拽排序、裁切 |

**关键交互**：冲突可定位；自动推断值显式标注；旧数据不隐藏；双轨并排对照。

## 九、成片时间线（修订 P1-12）

V1 只说"`timeline_duration` 导出时计算"，没定归属。V2 定案：

| 项 | 归属 |
|---|---|
| 存储 | `timelines` 表（`D01-05 §4.13`） |
| 写入方 | **成片模块**（唯一） |
| 读取方 | 导出、字幕、配乐、UI |
| `total_duration` | 派生值 = Σ `entries[].duration_real`，写入时重算 |
| 与 `unit_duration` 的关系 | 无关：单元是"请求时长"，时间线是"实际采用时长" |

**三轨时长的最终归属**：

| 时长 | 载体 | 谁来改 |
|---|---|---|
| `story_duration` | `story_shots` | 导演 |
| `unit_duration` | `render_units` | 适配层 |
| `timeline_duration` | `timelines.total_duration` | 成片模块（自动汇总） |

## 十、接口稳定性

| 变更 | 破坏性 | 处理 |
|---|---|---|
| 加可选字段 | 否 | 直接加，`spec_version` 不变 |
| 加必填字段 | 是 | `spec_version` +1，旧数据按 S 级降级 |
| 加枚举值 | 否（读者）/ 是（switch） | 编译器与 QC 必须"未知值 → WARN 不崩" |
| 删枚举值 | 是 | 禁止，只标 deprecated |
| 表结构变更 | 视情况 | 只加列/加表 |
| 编译器逻辑变更 | 是 | `compiler_ver` +1 |

**`spec_version` 管数据形状，`compiler_ver` 管编译逻辑，必须分开**——否则无法判断"产物不同是数据变了还是程序变了"。
