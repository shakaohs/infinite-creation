## 一、统一接口约定（所有模块共同遵守）

| # | 约定 | 落地要求 |
|---|---|---|
| I1 | **单一输入源** | 所有模块只读 `story_shots` + 从表 + `scene_states`；**不得**读 `shots.video_prompt` 当输入（那是产物） |
| I2 | **单向** | 模块只能写自己那一层的表（见 §2 写权限表），跨层写一律视为 bug |
| I3 | **纯函数优先** | 连续性求解、编译、质检三类核心逻辑必须是纯函数：`(input) → (output, hash)`，无隐藏状态、无网络、无时钟依赖 |
| I4 | **幂等** | 同输入重复执行结果一致；产物表用 `hash` 唯一键去重 |
| I5 | **可溯源** | 任何产物必须能回答"从哪版输入、哪个版本的程序、哪条规则产生的" |
| I6 | **不猜** | 输入缺失时输出 `UNKNOWN` + 原因，不填充默认值冒充确定结果 |

### 1.1 各层写权限表

| 模块 | 可写表 | 只读表 | 严禁 |
|---|---|---|---|
| 剧本抽取 | `scene_states`、`assets` | `chapters` | 写 `story_shots` |
| 分镜创作（LLM） | `story_shots`、`shot_blockings`、`shot_actions` | `scene_states`、`assets` | 写 `shot_states`、写任何 `*_packages`、写 `qc_reports` |
| Continuity Engine | `shot_states` | `story_shots`、`shot_blockings`、`shot_actions`、`scene_states` | 改 `story_shots` 任何字段 |
| 适配层（切分） | `shots`（unit 级）、`render_unit_shots`（若拆分需要） | `story_shots` | 改 `story_duration` |
| Compiler | `prompt_packages` | `story_shots`、`scene_states`、`assets`、`target_profiles` | 改任何创作态字段 |
| QC | `qc_reports` | 全部（只读） | 改任何数据 |
| Repair | 无（只产出"建议补丁"） | `qc_reports`、`story_shots` | 直接改库 |
| DAG 调度 | `render_tasks`、`render_attempts` | `render_units`(视图)、`prompt_packages` | 改创作态、改产物 |
| Studio 前端 | 经 API 间接写 | 全部 | 绕过 API 直连 DB |

**Repair 为什么不能直接写库**：自动修复如果能改分镜，就回到"模型自证合格"的老路。正确形态是 Repair 产出 patch，由人（或带置信度阈值的自动应用策略）经 API 应用，且应用前后各跑一次 QC。

## 二、Continuity Engine（连续性引擎）

### 2.1 职责

把"每镜独立填写的空间事实"变成"一条连续的时空状态链"，并报告冲突。

### 2.2 接口

```js
/**
 * @param {Object} input
 * @param {string} input.projectId
 * @param {string} input.sceneKey
 * @param {Array<Shot>} input.shots        // 按 global_no 升序，含 blockings/actions
 * @param {SceneState} input.sceneState
 * @returns {Object} { states: Map<shotId, {in,out,conflicts}>, sceneConflicts: [], hash }
 */
export function solveContinuity({ projectId, sceneKey, shots, sceneState }) { … }
```

### 2.3 输出契约

```json
{
  "states": {
    "sh_01HQ2K8X": {
      "in":  { "chars": {}, "props": {}, "costumes": {}, "env": {} },
      "out": { "chars": {}, "props": {}, "costumes": {}, "env": {} },
      "derived_from": "prev_shot:sh_01HQ2K7V",
      "conflicts": [
        { "code": "POSTURE_JUMP", "level": "FAIL", "shot": "sh_01HQ2K8X",
          "character": "as_char_roxanne", "from": "lying", "to": "standing",
          "msg": "姿态从躺到站，无 rise 动作", "suggest": "补 cog=rise 的动作或拆镜" }
      ]
    }
  },
  "sceneConflicts": [
    { "code": "AXIS_CROSS", "level": "FAIL", "shots": ["sh_01HQ2K7V","sh_01HQ2K8X"],
      "msg": "机位从罗克珊侧跨到哈罗德侧，无合法跨轴记录" }
  ],
  "hash": "sha256:…"
}
```

### 2.4 关键约束

- **只写 `shot_states`**：冲突不写回 `story_shots`（创作态不可被程序改）；
- **确定性**：给定相同 shots 必得相同 states（哈希可校验）；
- **增量**：只重算 `global_no ≥ 修改点` 的镜，前面的状态复用（性能要求：200 镜 < 200ms）。

## 三、Seedance Compiler

### 3.1 职责

把 RenderUnit（含 N 个 Shot）编译成 Seedance 2.x 的提示词。

### 3.2 接口

```js
/**
 * @param {Object} input
 * @param {RenderUnit} input.unit            // 含 unit_duration / seam / 所属 shots
 * @param {Array<Shot>} input.shots
 * @param {SceneState} input.sceneState
 * @param {TargetProfile} input.profile      // seedance25
 * @param {Array<Asset>} input.assets
 * @returns {{ body: string, format: string, refPack: Array, warnings: [], compiledHash: string }}
 */
export function compileSeedance(input) { … }
```

### 3.3 输出契约

| 字段 | 说明 |
|---|---|
| `body` | 完整提示词（现有七段式/九字段结构） |
| `format` | `seedance_seven`（沿用现模板） |
| `refPack` | `[{tag:'@图片1', assetId, path, hash}]` —— **按 unit 内首次出现顺序编号** |
| `warnings` | 编译期告警（如"镜 3 动作时长 2.1s > 剩余时长 1.8s"） |
| `compiledHash` | `sha256(sourceSpecHash + profileVer + compilerVer)` |

### 3.4 编译规则（与现状继承）

1. 每镜一行时间轴，格式沿用 `buildSegment` 的 `tsFmt(from)-tsFmt(to) [镜头N] …`；
2. `blocking` 由 `shot_blockings` + `scene_states` 渲染（**不由模型手写**）；
3. 时长必须 `Σ story_duration ≤ unit_duration`，超出则**不编译**，返回 `UNIT_OVERFLOW`；
4. 提示词中**不得出现** H3 特有语法（六段式 `subject_definitions` 等），也不得出现模型名。

## 四、MiniMax H3 Compiler

### 4.1 职责

把**同一份** RenderUnit + Shot 编译成 H3 的 Ref2VA 六段式。

### 4.2 接口

```js
export function compileH3(input) { … }   // 入参同 Seedance，profile=h3
```

### 4.3 输出契约

| 字段 | 说明 |
|---|---|
| `body` | 六段式全文（`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`） |
| `format` | `ref2va_six`（有参考图）/ `t2va_three`（无参考图） |
| `refPack` | `<Picture N>` 与 `<Subject N>` 同号映射 |
| `compiledHash` | 同上 |

### 4.4 编译规则

1. 段内时间轴用 `At 00:SS.mmm` 递增（首镜无时间戳）；
2. 站位声明从 `shot_blockings` 生成，**逐字沿用**，不得另起左右；
3. 单段时长受 `profile.max = 15` 约束，超限 → 适配层应在编译前已切好单元；
4. 无参考图 → 自动降级 `t2va_three`。

### 4.5 双编译器同源验证（需求书"两个模型用同一份分镜"的可检验证明）

| 验证项 | 方法 | 通过标准 |
|---|---|---|
| 输入同源 | 两编译器的 `sourceSpecHash` | **必须逐字相同** |
| 事实一致 | 从两份 body 中提取"人物位置/景别/台词" | 语义一致（人工抽检 5 单元） |
| 时长一致 | Seedance 的 Σ 时长 vs H3 的 Σ 时长 | 相等（都等于 Σ story_duration） |
| 切换不漂移 | 同单元先后用两编译器出片 | 站位/朝向不反转（画面比对） |
| 反向污染检测 | 检查 Seedance body 是否含 H3 段名，反之亦然 | 0 命中 |

**`sourceSpecHash` 的计算**（两个编译器必须用同一实现）：

```js
function sourceSpecHash(shots, sceneState) {
  const payload = shots.map(s => ({
    no: s.global_no, size: s.shot_size, dir: s.cam_direction, h: s.cam_height,
    mv: s.movement, amp: s.movement_amp, dur: s.story_duration,
    vc: s.visual_content, dlg: s.dialogue, spk: s.speaker_ids,
    block: s.blockings.map(b => [b.character_id, b.position_abs, b.facing, b.gaze_target, b.posture, b.in_frame]),
    act: s.actions.map(a => [a.actor_id, a.action_type, a.tier, a.t_from, a.t_to, a.contact_json]),
  }));
  return sha256(JSON.stringify({ scene: sceneState.coord_system, shots: payload }));
}
```

**这个哈希就是"同一份导演分镜"的机器可读证据。**

## 五、适配层（RenderUnit 切分）

### 5.1 职责

按 TargetProfile 把 Shot 序列切成生成单元。**不属于任何编译器**（否则两个编译器会切出不同的单元）。

### 5.2 接口

```js
/**
 * @returns {{ units: [{shots: [shotId], unitDuration, startNo, endNo}], warnings: [] }}
 */
export function splitIntoUnits({ shots, profile, seamPolicy }) { … }
```

### 5.3 切分规则

```
从左往右累加 story_duration：
  if (累加 + 下一镜 > profile.max)  → 在「上一个 is_cut_point=1 的镜」后切
  if (还有剩余但 < profile.shortFloor) → 并入上一单元（若合并后 ≤ max）
  if (整段 < profile.shortFloor)     → 标记 SHORT_UNIT（允许，但需理由）
```

**关键**：切点只能落在 `is_cut_point=1` 的镜后——这是 D01-02 J 区设计的直接用途，避免劈镜。

### 5.4 输出落库

`units[].shots` 写 `shots.id` 与 `story_shots.render_unit_id`。若一镜被拆到两个单元（不应发生，但兜底）→ `UNIT_SPLIT_SHOT` FAIL。

## 六、自动质检（QC）

### 6.1 职责

判定"是否合格"，**不修**。

### 6.2 接口

```js
/**
 * @param {'shot'|'unit'|'package'|'video'} targetType
 * @returns {{ level:'pass'|'warn'|'fail', hits:[{code,level,msg,field,suggest}] }}
 */
export function qcCheck({ targetType, targetId, rulesetVer }) { … }
```

### 6.3 规则挂载点（规则从哪来）

| 规则集 | 来源 | 检查对象 | 现状对应 |
|---|---|---|---|
| `spec` | D01-02 §15（V-01～V-15） | `story_shots` | 现有 `pickShotFields` + `validateShotContent` 升级 |
| `blocking` | D01-04 §11（S-01～S-17） | `shot_blockings` + `shot_states` | **新增**（现状无） |
| `action` | D01-03 §8（A-01～A-14） | `shot_actions` | **新增** |
| `prompt` | 现有 `skill-check.js` + Python 脚本 | `prompt_packages.body` | 已实现（h3_lint / finalcheck / validate_prompt） |
| `video` | D-08（未来） | `render_attempts.output_path` | 未实现，仅留位 |

### 6.4 输出示例

```json
{
  "targetType": "shot", "targetId": "sh_01HQ2K8X", "level": "fail",
  "hits": [
    { "code": "V-09", "level": "fail", "field": "dialogue",
      "msg": "台词 48 字 / 4.5 秒 = 10.7 字/秒，超上限 3.5", "suggest": "缩到 15 字或延长到 14 秒" },
    { "code": "S-13", "level": "warn", "field": "blockings.as_char_roxanne.distance_to_camera",
      "msg": "中景景别下人物距机位 2.4m，取景半径偏大", "suggest": "拉近至 1.8m 或改中全景" }
  ]
}
```

### 6.5 铁律

- QC **只读**，不产生任何数据修改；
- QC 结果必须带 `ruleset_ver`，规则变了旧结论可判为过期；
- **禁止 QC 调用 LLM 判定"是否合格"** —— 语义类判断（如"这镜有没有戏剧价值"）只能作为 LLM 的建议（INFO 级），不能作为 PASS/FAIL 依据。

## 七、自动修复（Repair）

### 7.1 职责

依据 QC 的 FAIL 产出**补丁建议**，不直接落库。

### 7.2 接口

```js
/**
 * @returns {{ patches: [{targetType, targetId, field, from, to, confidence, reason}], needsHuman: bool }}
 */
export function proposeRepair({ qcReport, shots, sceneState }) { … }
```

### 7.3 可自动修复 vs 必须人工

| FAIL 类型 | 可否自动 | 理由 |
|---|---|---|
| `V-09` 台词超速 | ⚠️ 半自动（只给建议，删除台词需人确认） | 删台词改剧情 |
| `V-11` 运镜-幅度矛盾 | ✅ 可自动（补 `movement_amp`） | 纯字段补全 |
| `V-12` 切点非法 | ✅ 可自动（移动单元边界） | 不改创作 |
| `S-16` 坐标缺失 | ⚠️ 半自动（按 §6.3 规则推断，置信度低需确认） | 可能猜错 |
| `S-05` 越轴 | ❌ 必须人工 | 涉及叙事意图 |
| `A-09` 动作塞不下 | ❌ 必须人工（拆镜或延时长） | 改创作 |
| `S-09` 道具凭空出现 | ⚠️ 半自动（补 `absent→held` 的取用动作） | 可能臆造 |

### 7.4 应用流程

```
QC FAIL → proposeRepair → 人工审核（Studio 侧栏逐条接受/拒绝）
        → API 应用 patch → 重跑 Continuity → 重跑 QC → 对比前后 hits
```

**回归要求**：应用补丁后若新增 FAIL（修一个坏两个）→ 自动回滚该补丁并标 `REPAIR_REGRESSION`。

## 八、渲染调度（DAG）

### 8.1 节点类型（未来 D-11 的骨架）

| 节点 | 输入 | 输出 | 幂等键 |
|---|---|---|---|
| `split_units` | shots + profile | units | `(projectId, chapterId, profileVer, specHash)` |
| `compile` | unit + track | package | `(unitId, track, compiledHash)` |
| `qc_package` | package | qc_report | `(packageId, rulesetVer)` |
| `render` | package + params | task/attempt | `(packageId, params, seed?)` |
| `qc_video` | attempt | qc_report | `(attemptId, rulesetVer)` |
| `assemble` | attempts(selected) | timeline | `(projectId, [attemptIds])` |

### 8.2 依赖关系

```
split_units ──► compile(seedance) ──► qc_package ──► render ──► qc_video ──┐
            └─► compile(h3) ────────► qc_package ──► render ──► qc_video ──┴─► assemble
```

**两条编译支路互不阻塞**：Seedance 挂了不影响 H3 出片——这是"同源分叉"的工程价值。

### 8.3 断点与重试

- 每个节点的输出落表即断点，重跑从缺输出的节点开始；
- `render` 失败重试**新增 `attempt`**，不改旧记录；
- 同一 `(packageId, params)` 已 `done` 则跳过（幂等跳过，沿用现有 `generateShotVideo` 思路）。

## 九、Studio 工作台

### 9.1 读写契约

| 面板 | 读 | 写 | 只读展示 |
|---|---|---|---|
| 分镜列表 | `story_shots` + 影子镜 | 拖拽改序 → `shot_no/global_no` | — |
| 镜详情 | ShotSpec 全字段 | 文本与枚举字段 | `spec_source` 标记 |
| 站位面板 | `shot_blockings` + `scene_states.coord_system` | 逐人 12 要素 | 平面图预览（由 norm_xy 渲染） |
| 动作面板 | `shot_actions` | 动作链（按 tier 动态显示字段） | 时间轴条 |
| 连续性视图 | `shot_states` + `conflicts` | ❌ 只读 | 冲突红点、跳转定位 |
| 编译预览 | `prompt_packages` 多版本 | ❌ 只读（触发重新编译） | 版本 diff |
| 质检报告 | `qc_reports` | ❌ 只读 | 按镜聚合 |

### 9.2 关键交互要求

1. **冲突可定位**：`conflicts` 的每条都要能点跳转到对应镜与字段；
2. **不静默改**：任何自动推断值（`confidence<0.7`）必须显式标注，用户确认后才转 `manual`；
3. **旧数据不隐藏**：legacy 镜必须显示「未结构化」标记，且提供"结构化为 ShotSpec"入口；
4. **双轨对照**：同一单元可并排看 Seedance / H3 两份编译结果。

## 十、数据流转时序（一次完整生产）

```
① 用户上传剧本
   set_chapter_script → chapters.script
   └─(程序) ensureScriptAssets → assets + scene_states（坐标系统初值）

② 分镜创作（LLM）
   set_storyboard → story_shots + shot_blockings + shot_actions
   └─(程序) 校验 V-01..V-15 + A-01..A-14 → 不合格直接拒绝写入

③ 连续性求解（程序）
   solveContinuity → shot_states（含 conflicts）
   └─ FAIL 冲突 → 阻断，要求改分镜

④ 适配切分（程序）
   splitIntoUnits(profile) → render_units（写回 shots 结构）

⑤ 双轨编译（纯函数）
   compileSeedance → prompt_packages(track=seedance)
   compileH3       → prompt_packages(track=h3)
   └─ 两者 sourceSpecHash 必须相同（校验）

⑥ 编译质检（程序）
   qc_package → qc_reports
   └─ FAIL → proposeRepair → 人工 → 回到 ②

⑦ 渲染（调度）
   render → render_tasks → render_attempts → 视频文件

⑧ 成片（程序）
   assemble → timeline（Σ 选中 attempt）
```

**每一步的产物都在表里**，因此可以：断点续跑、换模型重编译、A/B 对比、追责"哪一步出的问题"。

## 十一、接口稳定性约定

| 变更类型 | 是否破坏兼容 | 处理 |
|---|---|---|
| 新增可选字段 | 否 | 直接加，`spec_version` 不变 |
| 新增必填字段 | 是 | `spec_version` +1，旧数据按 S 级别降级 |
| 枚举新增值 | 否（对读者）/ 是（对 switch） | 编译器与 QC 必须用"未知值 → WARN 而非崩溃" |
| 枚举删除值 | 是 | 禁止（只标记 deprecated） |
| 表结构变更 | 视情况 | 只加列/加表，不改不删 |
| 编译器逻辑变更 | 是（产物不同） | `compiler_ver` +1，旧 package 保持可读 |

**`compiler_ver` 与 `spec_version` 必须分开**：前者管"怎么编"，后者管"数据长什么样"。混在一起就无法判断"是数据变了还是编译器变了导致产物不同"。
