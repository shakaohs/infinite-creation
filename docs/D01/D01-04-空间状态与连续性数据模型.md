# D01-04 空间状态与连续性数据模型

> 依赖：`D01-01`（实体层级、站位权威上移）、`D01-02`（ShotSpec 主表）、`D01-03`（动作模型）
> 本文回答：**站位怎么存、状态怎么继承、越轴怎么算、连续性怎么判。**
> 这是现状最大的结构性空洞（审计 03 §5：`blocking` 覆盖率 20%，跨段继承"未实现"）。

---

## 一、现状为什么会漂（三个根因）

| 根因 | 表现 | 代码位置 |
|---|---|---|
| **① 无空间基线** | 每段自己写一套方位，段与段之间没有共享坐标系 | `storyboard-plan.json` 的 `anchors` 存文件、不随镜走、不参与机检 |
| **② 无状态继承** | `blocking` 每段重写，写的人只能凭记忆 | `prompts.js:2811` 只注入"本段唯一方位权威" |
| **③ 无越轴判定** | 机检只核"有没有写 blocking"，不判左右矛盾 | 审计 03 §5「越轴检测：部分实现」 |

后果：换模型、换人重跑、跨会话续跑时，站位信息无法机械复用 → 只能重新猜 → 猜错就是越轴/漂移/分身。

**D01 的解法**：把空间拆成**三层 + 一套求解算法 + 一张判定矩阵**，让"位置"成为数据而不是描述。

---

## 二、三层空间模型

```
Scene 层：SceneState（场基线，一场一份，模型无关）
   ├─ 坐标系（方位基 + 垂直层级 + 归一化网格）
   ├─ 固定物（fixtures，不可移动，可作依托）
   ├─ 出入口（主/次）
   └─ 轴线（axis_lock：谁在左、谁在右、机位必须在哪侧）

Shot 层：ShotBlocking（逐人一行，每镜每人一份）
   ├─ 绝对方位（人读：北窗下·靠东墙）
   ├─ 归一化坐标（程序算：x,y,z ∈ [0,1]）
   ├─ 朝向 / 视线 / 姿态 / 距离 / 遮挡 / 手位 / 事务 / 在画
   └─ 权力位阶（高/中/低）

Transition 层：ShotState（每镜首尾状态差异集）
   ├─ state_in：本镜开始时的人物/道具/环境状态
   └─ state_out：本镜结束时的状态
```

**为什么要"两套坐标"**：

- **文字方位**（`position_abs`）给人看、给提示词用：「病床右侧·床头柜旁」是导演能理解、模型能渲染的表达；
- **归一化坐标**（`norm_xy`）给程序算：越轴、距离、遮挡、位移连续性都需要数值；
- 二者**互为校验**：文字说"床右侧"而坐标为 (0.2, 0.5)（左侧）→ FAIL「方位与坐标矛盾」。

## 三、SceneState：场基线（一场一份）

表 `scene_states`，唯一键 `(project_id, scene_key)`。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `scene_key` | TEXT | ✅ | 场次键，如 `S02_病房` |
| `scene_id` | TEXT | ⭕ | 场景资产 id（一个场景资产可用于多场） |
| `coord_system` | JSON | ✅ | 坐标系定义，见 §3.1 |
| `fixtures` | JSON | ✅ | 固定物列表，见 §3.2 |
| `entries` | JSON | ✅ | `{main:'门', secondary:'阳台门'/null}` |
| `axis_lock` | JSON | ⭕ | 轴线锁，见 §3.3（S1 以上必填） |
| `power_geometry` | JSON | ⭕ | 权力几何场初/场末对照（`blocking-direction.md` §二铁律：场末必须 ≠ 场初） |
| `crowd_switch` | ENUM | ⭕ | 群像开关 `A`（逐人写）/`B`（只写密度）/`C`（关闭） |
| `time_of_day` | TEXT | ⭕ | 时间/光线基线（夜/晨/午后），跨镜变化须有事件依据 |
| `state_rev` | INT | ✅ | 版本号，任何字段变更 +1（供编译缓存失效） |

### 3.1 `coord_system` 结构

```json
{
  "basis": { "north": "正对主窗", "south": "回望入口", "east": "病床侧", "west": "走廊侧" },
  "levels": [
    { "name": "floor", "offset_m": 0 },
    { "name": "bed_level", "offset_m": 0.6 },
    { "name": "step", "offset_m": 0.5 }
  ],
  "grid": { "x": "east→west", "y": "south→north", "z": "floor→ceiling" },
  "active_area": "病床与床头柜之间的 1.5m×1.2m 区域"
}
```

**来源**：`blocking-direction.md` §1.2「场景坐标系」（方位基 + 垂直层级 + 中央活动区 + 入口 + 固定物），逐项落成字段。

**关键约束**：
- `basis` 用**绝对方位**（东南西北 + 固定参照物），**禁用"画面左/右"**——画面方位随镜头翻转，物理方位不会（`blocking-direction.md` 硬规则 1）；
- `grid` 定义归一化方向，供 `norm_xy` 解释。x/y ∈ [0,1] 覆盖 `active_area` 的外接矩形。

### 3.2 `fixtures` 结构（固定物 = 空间锚点）

```json
[
  { "id": "fx_bed",   "name": "病床",     "asset_id": "as_prop_bed",
    "zone": [0.05, 0.30, 0.55, 0.95], "movable": false, "can_lean": true },
  { "id": "fx_table", "name": "床头柜",   "asset_id": "as_prop_nightstand",
    "zone": [0.30, 0.35, 0.50, 0.55], "movable": false, "can_place": true },
  { "id": "fx_window","name": "百叶窗",   "asset_id": null,
    "zone": [0.70, 0.00, 1.00, 0.40], "movable": false, "light_source": true }
]
```

- `zone`：`[x1, y1, x2, y2]` 归一化占位矩形——用于**位移穿模检测**（D01-03 A-03）与**遮挡判定**；
- `can_lean` / `can_place`：可作为依托/置物面——对应 `blocking-direction.md`「每步有依托」「落点」；
- `movable=false` 的固定物**不得**出现在 `shot_actions.path` 的 `to` 坐标里（人不能站进病床）。

**为什么固定物要进库**：现状锚点只活在 `storyboard-plan.json`（文件态），镜行无法引用，机检无法校验"他靠的那根柱子是否存在"。进库后可做引用完整性检查。

### 3.3 `axis_lock` 结构（轴线锁）

```json
{
  "pair": ["as_char_harold", "as_char_roxanne"],
  "left": "as_char_roxanne",
  "right": "as_char_harold",
  "camera_side": "left",
  "axis_line": [[0.35, 0.55], [0.25, 0.85]],
  "cross_allowed": [
    { "after_shot": "sh_01HQ2K7V", "reason": "中性空镜过渡", "type": "neutral_insert" }
  ]
}
```

| 字段 | 含义 | 校验用途 |
|---|---|---|
| `pair` | 轴线由哪两人（或人与门）定义 | 轴线只对这两人有效 |
| `left` / `right` | 物理左右归属 | 与 `shot_blockings.norm_xy` 的 x 值比对 |
| `camera_side` | 机位必须待在哪一侧（`left`/`right`） | **越轴判定基准** |
| `axis_line` | 视线连线（归一化两点） | 计算机位在轴的哪侧 |
| `cross_allowed` | 合法跨轴记录（必须给理由与类型） | 白名单式豁免，禁止"无记录跨轴" |

**为什么 `cross_allowed` 要显式记录**：跨轴不是绝对禁止，而是"必须有叙事理由"（中性空镜、人物走到对面、主观视角切换）。现状没有任何机制区分"合法跨轴"与"穿帮越轴"，所以只能一律禁止，结果要么僵化要么失控。

## 四、ShotBlocking：逐人空间（12 字段）

表 `shot_blockings`，一镜 N 行（每人一行，**含画外人物**）。

| # | 字段 | 类型 | 必填(S级) | 说明 | 来源 |
|---|---|---|---|---|---|
| 1 | `shot_id` | FK | all | 所属镜 | — |
| 2 | `character_id` | FK | all | 人物资产 id | — |
| 3 | `position_abs` | TEXT | all | 绝对方位，如「病床右侧·床头柜旁 0.6m」 | `blocking-direction.md` §1.2【人物初始位】 |
| 4 | `norm_xy` | JSON | **S2+** | `[x, y, z]` 归一化坐标 | 新增（供算法） |
| 5 | `anchor_object` | TEXT | S1+ | 依托物（`fixtures.id` 或道具 id） | 硬规则 2「每步有依托」 |
| 6 | `behind_object` | TEXT | S1+ | 身后背景物（防"背后凭空长出东西"） | 一行式六要素之一 |
| 7 | `facing` | ENUM+度 | all | 朝向：`N/S/E/W` + 角度简化（`front_to_cam`/`side`/`back`） | — |
| 8 | `gaze_target` | TEXT | S1+ | 视线落点：`as_char_roxanne.face` / `fx_window` / `off_screen_left` | — |
| 9 | `posture` | ENUM | all | `standing`/`sitting`/`sitting_supported`/`crouch`/`kneel`/`lying`/`lean`/`walking` | — |
| 10 | `distance_to_camera` | REAL | S2+ | 估距（m），用于景别-取景半径校验 | `asset-spatial-ledger.md` §8 |
| 11 | `occlusion` | ENUM | S2+ | `none`/`partial(部位)`/`half`/`full` | — |
| 12 | `hand_state` | TEXT | S1+ | 手位与持物：`右手持纸`/`双手空`/`左手扶栏` | `blocking-direction.md` §五【道具账】 |
| 13 | `current_task` | TEXT | S1+ | 手头事务（静止人物的"存在理由"） | 一行式六要素 |
| 14 | `in_frame` | BOOL | all | 1=在画内，0=画外（**画外者也要登记**） | 画内/画外清单 |
| 15 | `power_level` | ENUM | S2+ | `high`/`mid`/`low`（权力几何） | `blocking-direction.md` §二 |
| 16 | `instance_anchor` | TEXT | S3+ | 位移后的当前态锚点（"保持镜2进言位"） | 单实例铁律 7 |
| 17 | `single_instance` | BOOL | all | 默认 1，标记"全程只有一个身体" | 单实例铁律 |

> 17 行含 shot_id/character_id 两个外键；需求书的 10 项空间要素（位置/相对位置/朝向/视线/距离/与道具关系/姿态/遮挡/机位关系）全部覆盖。**相对位置**由 `norm_xy` 两两相减得出，不单独存（避免冗余不一致）。

### 4.1 `norm_xy` 的必要性（这是越轴能算的前提）

```json
{ "x": 0.35, "y": 0.62, "z": 0.0, "confidence": 0.8 }
```

- `x`：东西向（0=东墙，1=西墙，按 `coord_system.grid`）
- `y`：南北向（0=南/入口，1=北/主窗）
- `z`：垂直（0=地面层，0.6=床面层）
- `confidence`：填写置信度（人工填 1.0，从文字推断 0.5–0.7），低置信度不参与严格判定

**取值方式**：
1. 模型在 S2 以上必须给（受约束：只能落在 `active_area` 或 `fixtures` 边缘）；
2. 或由程序从 `position_abs` 的半结构化文本推断（规则见 §6.3）；
3. 缺省时标记 `confidence=0`，越轴检测降级为"只比文字方位"，并 WARN。

### 4.2 相对位置的计算（不落库）

```python
# 两人距离（归一化 → 米，需 coord_system 给出 active_area 的实际尺寸）
dx = (b.x - a.x) * area_w
dy = (b.y - a.y) * area_h
distance = sqrt(dx² + dy²)

# 谁在谁左边（以摄影机为基准）
cam = camera_position(shot)                 # 由 cam_direction + cam_height + 机位估距推算
to_a = a.xy - cam.xy
to_b = b.xy - cam.xy
a_is_left = cross(to_a, to_b).z > 0         # 叉积符号
```

**这解决了"画面左右"的歧义**：现状提示词里的"画面左/右"是渲染结果、不可预知；此处是**物理坐标 + 机位推算**，可复现、可校验。

## 五、ShotState：首尾状态与继承

表 `shot_states`，1 镜 1 行。

| 字段 | 类型 | 说明 |
|---|---|---|
| `shot_id` | FK PK | — |
| `state_in` | JSON | 本镜开始时的状态 |
| `state_out` | JSON | 本镜结束时的状态 |
| `derived_from` | TEXT | `state_in` 的求解来源：`prev_shot:<id>` / `scene_baseline` / `manual` |
| `conflicts` | JSON | 求解时发现的冲突（空 = 无冲突） |
| `state_source` | ENUM | `solved`（程序求解）/ `none`（未结构化）/ `manual`（人工填） |

### 5.1 状态结构（键值集，不是自由 JSON）

```json
{
  "chars": {
    "as_char_harold":  { "pos": [0.30,0.70], "posture": "standing", "facing": "W", "hand": "右手持纸", "gaze": "roxanne" },
    "as_char_roxanne": { "pos": [0.15,0.60], "posture": "sitting_supported", "facing": "E", "hand": "右手撑床", "gaze": "harold" }
  },
  "props": {
    "as_prop_notice": { "state": "held", "owner": "as_char_harold", "hand": "right" },
    "as_prop_bed":    { "state": "fixed" }
  },
  "costumes": { "as_char_harold": "as_costume_harold_suit" },
  "env": { "light": "cold_day", "time": "morning", "door": "closed" }
}
```

**四个顶层键固定**（`chars` / `props` / `costumes` / `env`），子键为资产 id——这样状态可以**按 id 求差集**，而不是文本比对。

### 5.2 继承算法（求解 State In）

```
输入：shot（当前镜）、prev_shots（同场内已完成的镜，按 global_no 倒序）、scene_states
输出：state_in、derived_from、conflicts

Step 1  找最近的前序镜 P（同 scene_key 且 global_no < 本镜）
        └ 无前序 → state_in = scene_baseline（由 SceneState.axis_lock 与首镜 blocking 生成），derived_from='scene_baseline'

Step 2  state_in.chars = P.state_out.chars（先全量沿用）

Step 3  与本镜 shot_blockings 比对，逐人求差：
        ├ 位置差异（norm_xy 距离 > 0.15）→ 需要 locomotion 动作，否则 conflict=POSITION_JUMP
        ├ 姿态差异（posture 变）        → 需要 cog 变化动作，否则 conflict=POSTURE_JUMP
        ├ 朝向差异（> 90°）             → 需要动作或明确切镜理由，否则 conflict=FACING_FLIP
        ├ 视线差异                     → 允许（视线可自由移动），不产生 conflict
        └ 手位差异（持物变化）          → 需要 manipulation 动作，否则 conflict=HAND_JUMP

Step 4  state_in.props = P.state_out.props
        ├ 道具出现在本镜 prop_ids 但 P 中 'absent' → conflict=PROP_APPEAR（凭空出现）
        ├ 道具 'held' 但 owner 在本镜 in_frame=0 且道具未登记 → conflict=PROP_ORPHAN
        └ 道具 held → placed 但本镜无 manipulation → conflict=PROP_TELEPORT

Step 5  本镜有剧情时间跳跃标记（time_jump=true）→ 降级为 WARN，允许重设

Step 6  state_out = 由 state_in + 各动作 result/end_state 逐条应用得到
        （动作按 t_from 排序，依次 apply）
```

**关键设计：`state_in` 是"求解出来的"，不是"模型填的"。**

- 模型只填 `shot_blockings`（本镜事实）与 `shot_actions`（本镜动作）；
- 程序从上一镜 `state_out` 推出本镜 `state_in`，再与模型填的事实比对——**不一致就报冲突**；
- 这直接消除"每镜重新猜位置"的根源，也避免模型为了"看起来连贯"而编造状态。

> 现状对比：`blocking` 每段重写，写的人只能凭记忆；新模型里"上一镜结束他在床右侧 0.6m"是数据，本镜若写"床左侧"，程序立刻发现。

### 5.3 `state_out` 的生成

```
state_out = state_in
for action in shot_actions (按 t_from 升序):
    state_out.chars[action.actor_id] ← action.end_state        # 覆盖
    state_out.props ← apply(action.result.prop_delta)
    state_out.env   ← apply(action.result.env_delta)（若有）
```

**校验**：`state_out` 与下一镜 `state_in` 必须**同源**（下一镜的 `derived_from = prev_shot:<本镜>`），且差异集必须被本镜动作覆盖——这是"不要求所有字段相等、但要求变化有依据"的实现方式。

## 六、连续性合法性判定矩阵

需求书明确：**State Out 与下一镜 State In 不要求完全相等，但要判断变化是否合法、是否有动作依据、是否冲突。**

### 6.1 判定矩阵

| 变化类型 | 合法条件 | 无依据时 | 判据 |
|---|---|---|---|
| **位置变化 ≤0.15** | 自然（微调站位） | 放行 | 归一化距离 |
| **位置变化 0.15–1.5** | 需 `locomotion` 动作，`path.to` ≈ 新位置 | `POSITION_JUMP` FAIL | 距离 + 动作存在性 |
| **位置变化 >1.5**（同场） | 需位移动作 **或** 明确 `time_jump` | `TELEPORT` FAIL | — |
| **跨场位置变化** | 合法（换场景） | — | `scene_key` 不同即放行 |
| **姿态变化**（坐↔站） | 需 `cog=rise/lower` 的动作 | `POSTURE_JUMP` FAIL | posture 枚举差 |
| **朝向变化 ≤45°** | 自然（转头） | 放行 | — |
| **朝向变化 >90°** | 需动作（转身）或切镜到新机位 | `FACING_FLIP` WARN | facing 角差 |
| **视线变化** | **始终合法**（视线自由） | 放行 | — |
| **手位/持物变化** | 需 `manipulation` 动作 + `contact` | `HAND_JUMP` FAIL | hand_state 差 + 动作 |
| **道具 held→placed** | 需接触动作（放下/掉落） | `PROP_TELEPORT` FAIL | props 状态机 |
| **道具 absent→held** | 需取用动作 | `PROP_APPEAR` FAIL | — |
| **道具 owner 变更** | 需交接动作（递交/夺取） | `PROP_HANDOVER` FAIL | owner 差 |
| **服装变化** | 需换装事件（更衣/时间跳跃） | `COSTUME_JUMP` FAIL | costume_ids 差 |
| **年龄变体变化** | 需闪回/时间跳跃标记 | `AGE_JUMP` FAIL | age_ids 差 |
| **场景变化** | 必须换 `scene_key` | `SCENE_MISMATCH` FAIL | — |
| **光线/时间变化** | 需 `env` 事件（开灯/日落/时间跳跃） | `LIGHT_JUMP` WARN | env 差 |
| **人物入场/离场** | 需位移动作（走入/走出画）或切镜 | `CHAR_POP` FAIL | character_ids 差 |

### 6.2 冲突严重度分级

| 级别 | 含义 | 处置 |
|---|---|---|
| `FAIL` | 硬冲突，必然穿帮 | 阻断编译，要求改分镜 |
| `WARN` | 可疑，需人工确认 | 放行但记录，进 `qc_reports` |
| `INFO` | 记录了变化，有依据 | 仅审计用 |

### 6.3 `position_abs` → `norm_xy` 的推断规则（回填用）

```
输入："病床右侧·床头柜旁 0.6m"
1. 抽取方位词：右侧/左侧/东/西/南/北/中间/门口/窗边
2. 匹配 fixtures：病床 / 床头柜 → 取该 fixture 的 zone
3. 组合：base = fixture.zone 的中心；offset = 方位词方向 × 0.6m（换归一化）
4. 无方位词 → 取 active_area 中心，confidence=0.3
5. 无法解析 → norm_xy=null，confidence=0
```

**明确不猜**：解析不出就置空 + 低置信度，绝不"估一个看起来合理的坐标"。这是"宁可空不乱绑"原则在空间层的延续。

## 七、S0–S4 分级与必填强度

级别**由数据推导**，不由模型声明（防止"全填 S0 逃避校验"）：

```
level = S0
if (chars_in_frame >= 2)                              level = S1
if (chars_in_frame >= 3 || any(prop 被 2 人以上接触))  level = S2
if (any(locomotion) || any(path.to))                  level = S3
if (any(combat) || chars_total >= 5 || 群像开关=A)     level = S4
```

| 级别 | 必填项 | 校验强度 |
|---|---|---|
| **S0** | position/facing/posture/in_frame | 只校验枚举与非空 |
| **S1** | + anchor/behind/gaze/hand/current_task + `axis_lock` | 校验轴线存在 |
| **S2** | + norm_xy/distance/occlusion/power_level | **校验越轴、取景半径、遮挡** |
| **S3** | + path 完整性 + state_in/out | **校验位移连续、状态断裂** |
| **S4** | + 逐动作接触点 + 群像开关 + 单实例锚 | 全量校验 |

**设计意图**：把"全片都要写、结果 80% 没写"变成"按复杂度强制、级别由数据推导、级别越高校验越严"。单人特写不会被逼着写 17 个字段，多人对峙则一个字都不能省。

## 八、越轴检测（真正的机检）

### 8.1 算法

```
输入：shot（本镜）、prev（同场前一镜，可空）、axis_lock、shot_blockings.norm_xy

Step 1 取机位位置
       cam_pos = derive_camera_pos(shot)
       # 由 cam_direction + cam_height + 主要人物的 distance_to_camera 反推：
       # 面向 three_quarter + distance 1.8m + x 偏左 → cam 在 A 侧偏左

Step 2 判断机位在轴的哪一侧
       axis = axis_lock.axis_line            # [[x1,y1],[x2,y2]]
       side = sign(cross(axis_vec, cam_pos - axis_p1))
       # side > 0 → 左侧，side < 0 → 右侧

Step 3 与上一镜比较
       if (side != prev.side):
           if (本镜在 cross_allowed 白名单) → INFO（合法跨轴）
           else if (本镜是中性镜/空镜/主观视角) → WARN（需补记录）
           else → FAIL「越轴：机位从 {prev.side} 跨到 {side}，无合法跨轴记录」

Step 4 画面左右一致性
       a_is_left = cross(to_a, to_b).z > 0
       if (a_is_left != (axis_lock.left == a.id)) → FAIL「左右反转」
```

### 8.2 与现状的区别

| 项 | 现状 | D01 |
|---|---|---|
| 依据 | 文本里"左侧/右侧"字样 | **物理坐标 + 机位推算** |
| 判定 | 只核"有没有写 blocking" | 计算机位侧别变化 |
| 跨轴 | 一律禁止（规则僵化） | 白名单 + 理由 + 类型 |
| 输出 | 无 | `FAIL/ WARN` + 具体哪两镜之间、跨了哪条轴 |

### 8.3 无法判定时的降级

当 `norm_xy` 缺失或 `confidence < 0.5`：
- 降级为"文字方位比对"：只检查 `position_abs` 里的东西南北是否与前镜矛盾；
- 输出 `AXIS_UNVERIFIED`（WARN 级），并在 UI 提示"本镜缺少坐标，无法验证越轴"。

**不假装通过**——这是与现状最重要的区别之一：现状是"没写也 PASS"，新模型是"没法验证就说没法验证"。

## 九、道具状态机

`props` 的 `state` 取值与转移：

```
absent ──(取用/拿出)──► held(owner, hand)
held ──(放下)──► placed(surface)
held ──(递交/被夺)──► held(new_owner, hand)
held ──(掉落)──► dropped(position)
placed ──(再次拿起)──► held
any ──(消耗/损毁)──► consumed / broken  （不可逆，除非剧情重置）
```

| 转移 | 必需动作字段 | 校验 |
|---|---|---|
| absent→held | `manipulation` + `contact(target=prop)` | 无动作 → `PROP_APPEAR` FAIL |
| held→placed | `manipulation` + `result.prop_delta` | 无 → `PROP_TELEPORT` FAIL |
| held→held(换人) | 两人同时在场 + 交接动作 | 无 → `PROP_HANDOVER` FAIL |
| held→dropped | 打击/失手动作 | — |
| →consumed/broken | 不可逆，须 `env` 或 `event` 标记 | 反向恢复 → FAIL「道具复活」 |

**四必写**（`blocking-direction.md` §五）：持有者 / 手位 / 落点 / 状态——恰好对应 `props[].state`、`owner`、`hand`、`state(完好/破损/入鞘)`。

**跨镜继承**：`state_in.props` 全量沿用上一镜 `state_out.props`；未被任何镜引用的道具自动置 `absent`（防"道具一直挂身上"）。

## 十二、与"每段重写 blocking"的关系

D01 **不废除** `shots.blocking`（兼容与提示词直接投喂仍需要它），但改变它的角色：

| 项 | 现在 | D01 之后 |
|---|---|---|
| 性质 | 唯一事实来源（人写的一段话） | **派生产物**（由 ShotBlocking + SceneState 生成） |
| 写法 | 每段重写 | 从数据渲染，格式固定 |
| 用途 | 直接进投喂提示词 | 进提示词前仍可润色，但**不参与机检判断** |
| 机检 | 只核"有没有" | 核"与结构化数据是否一致" |

生成规则（`blocking` 由结构化数据渲染）：

```
【段首站位声明】
@哈罗德（画面右 · 病床右侧床头柜旁 0.6m · 背靠百叶窗 · 侧身 45° 朝左 · 立 · 右手垂 · 施压等待）
@罗克珊（画面左 · 病床上床头抬高 30° · 半坐 · 仰视 · 右手撑床指尖收紧 · 抵抗）
轴线锁定：罗克珊在左、哈罗德在右，机位恒定在罗克珊一侧，全段禁越轴；位移仅限：哈罗德 1.2m → 0.6m
```

**这一步是"提示词可复现"的关键**：同一份 ShotBlocking 数据，无论重编译多少次、换谁执行，渲染出的站位声明都一样。
