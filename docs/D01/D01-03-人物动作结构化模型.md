# D01-03 人物动作结构化模型（第二轮修订）

> 依赖：`D01-02`（ShotSpec 字段字典）、`D01-04`（坐标体系）
> 本文回答：**动作怎么存才能被程序算；并行动作怎么算时长；动作时间线与镜头时间线什么关系。**
> 修订轮次：V2。V1 的问题是"把自然语言换成 JSON，但 JSON 里仍是自然语言"，本轮逐项改为可计算结构。

---

## 一、V1 的四个致命缺陷（评审 P0-2）

| # | V1 写法 | 为什么不能用 | V2 修正 |
|---|---|---|---|
| 1 | `path: {from:"床右侧 1.2m", to:"床右侧 0.6m"}` | 字符串无法计算位移距离、无法判穿模、无法与下一镜位置比对 | `path.from/to` 改为**坐标** `{x,y,z}`，原文字进 `label` |
| 2 | `result: {target_delta:"纸滑落一半垂在柜沿"}` | 无法推出道具最终状态，只能人读 | `result` 拆成 `char_delta` / `prop_delta` / `env_delta`，每项是**状态迁移**而非描述 |
| 3 | `end_state: {posture:"standing", hand:"双手空"}` | 没有位置，无法作为下一镜 `state_in` 的可计算来源 | `end_state` 必须含 `pos:{x,y}` + `props[]` 迁移结果 |
| 4 | 动作时长简单相加 | 两人同时动作会被算成两倍时长，误判"塞不下" | 引入**并行组**，组内取 max、组间相加 |

上一版虽写了"反应是独立行"，但没给 `trigger` 一个**可指向动作的 id**，导致"这个反应是谁引起的"仍无法查询。V2 修正。

## 二、三档粒度（保留 V1 设计）

| 档 | 必填字段 | 适用 | 依据 |
|---|---|---|---|
| **T1** `brief` | actor / type / init_state / trigger / result / end_state / t_from / t_to | 小动作：坐下、点头、递物 | `blocking-direction.md`「过渡招只需起点、受力点与状态继承」 |
| **T2** `standard` | T1 + path / speed / cog / contact / sync / body_parts | 有位移或接触 | 五段闭环 |
| **T3** `full` | 全 20 字段 + `force.chain` ≥8 环 | 关键重击 | `kinetic-chain-11.md` |

**自动判档**（程序判定，禁止模型自选）：

```
if (action_type=='combat' && is_key_blow)        → T3
else if (path.to || contact.target_id)           → T2
else                                             → T1
```

模型给 T1 但 `path.to` 非空 → 自动升 T2 + WARN；给 T3 但动作为"点头" → WARN「过度设计」。

| 3 | `actor_id` | TEXT | ✅ | T1 | 执行者；`env` 表示环境动作 |

| 18 | `recovery` | TEXT | ✅ | T2 | 收势 |

| 22 | `t_to` | REAL | ✅ | T1 | 镜内结束秒 |

### 3.1 `init_state`

```json
{
  "pos": { "x": 0.30, "y": 0.70, "z": 0 },
  "posture": "standing",
  "facing": "W",
  "cog": "stable",
  "hand": { "right": "持纸", "left": "空" },
  "gaze": "as_char_roxanne"
}
```

`pos` 必填（T1 起）——这是"可计算"的底线。若无法给出坐标，`pos=null` 且该动作降级为"不可计算动作"，不参与位置继承（`D01-04 §5` 会把它标为状态断裂）。

### 3.2 `trigger`（修订：可指向动作 id）

```json
{ "kind": "action",  "ref": "ac_01HQ2M01", "text": "对方把纸摔在柜上" }
{ "kind": "dialogue","ref": "line:2",      "text": "台词说完" }
{ "kind": "ambient", "ref": "sfx:monitor","text": "监护仪报警" }
{ "kind": "self",    "ref": "",            "text": "自主" }
```

`kind=action` 时 `ref` 必须是同镜或前镜的动作 id——**这是"反应动作关联触发动作"的实现**。校验：`ref` 不存在 → FAIL；`ref` 指向的动作 `t_to > 本动作 t_from` → WARN（因果倒置）。

### 3.3 `path`（修订：坐标形式）

```json
{
  "from": { "x": 0.30, "y": 0.70, "z": 0 },
  "to":   { "x": 0.26, "y": 0.66, "z": 0 },
  "via":  [ { "x": 0.28, "y": 0.68, "z": 0 } ],
  "move_type": "forward_step",
  "blocked_by": [],
  "distance_m": 0.62,
  "label": "床右侧 1.2m → 0.6m（病床与床头柜之间）"
}
```

| 字段 | 说明 |
|---|---|
| `from` / `to` | 归一化坐标（沿 `scene_states.coord_system.grid`），与 `shot_blockings.norm_x/y` 同源 |
| `via` | 必经点（绕开障碍） |
| `distance_m` | 由 `coord_system.active_area` 实际尺寸换算，**程序算，模型不填** |
| `label` | 人读文字（供提示词引用），**不参与计算** |
| `blocked_by` | 被绕开的 `fixtures.id` |

**穿模校验**：`from→to`（含 `via` 折线）与 `fixtures[].zone` 相交 → FAIL。这是"坐标化"换来的能力，V1 无法做。

### 3.4 `force`

```json
{
  "source": "右臂前摆，肩带动",
  "type": "downward_smash",
  "chain": ["蓄力（抬臂）", "肢体轨迹（下砸弧线）", "接触点（纸面拍柜）"]
}
```

T3 要求 `chain.length ≥ 8`（对应 11 环），T2 ≥ 3，T1 可空。

### 3.5 `speed`

```json
{ "profile": "sudden", "peak_at": 1.4, "avg_mps": 1.8 }
```

`profile ∈ constant / accelerate / decelerate / sudden / hold`。`sudden` 要求前置 `hold` 时间片（`D01-02 §10`），否则 WARN。

### 3.6 `body_parts`

```json
[
  { "part": "right_arm", "act": "抬至胸高后下压", "angle_from": 30, "angle_to": -15 },
  { "part": "left_shoulder", "act": "随之下沉" },
  { "part": "right_foot", "act": "前迈半步" }
]
```

`angle_from/to` 可选；有角度即可做"动作幅度"机检（越小越像静止）。

### 3.7 `contact`

```json
{
  "target_type": "prop",
  "target_id": "as_prop_notice",
  "point": "纸面中下部",
  "surface": "床头柜台面",
  "duration_ms": 120,
  "impulse": "medium"
}
```

`impulse ∈ light / medium / heavy`（替代模糊的"力度大/小"）。

### 3.8 `result`（修订：状态迁移，非描述）

```json
{
  "char_delta": {
    "as_char_harold": { "pos": [0.26,0.66], "hand": { "right": "空", "left": "空" }, "cog": "forward" }
  },
  "prop_delta": [
    { "prop_id": "as_prop_notice", "from": { "state": "held", "owner": "as_char_harold", "hand": "right" },
      "to":   { "state": "placed", "surface": "fx_table", "condition": "完好·一半垂在柜沿" } }
  ],
  "env_delta": []
}
```

| 键 | 内容 | 可计算性 |
|---|---|---|
| `char_delta` | 受影响角色的**新状态**（与 `end_state` 同结构） | 可直接覆盖 `state.chars[id]` |
| `prop_delta` | 道具的 `from → to` 状态迁移 | 可直接推 `state.props[id]`，且 `from` 必须等于当前状态（否则 FAIL「状态不一致」） |
| `env_delta` | 环境变化（门开、灯灭、时间推进） | 同样 from→to |

**这是"道具最终状态可计算"的实现**：`state_out.props = apply(result.prop_delta)`，不需要任何自然语言解析。

### 3.9 `end_state`

```json
{
  "pos": { "x": 0.26, "y": 0.66, "z": 0 },
  "posture": "standing",
  "facing": "W",
  "cog": "stable",
  "hand": { "right": "空", "left": "空" },
  "gaze": "as_char_roxanne"
}
```

**校验**：`end_state.pos` 必须等于 `path.to`（有位移时），容差 0.02；不位移则等于 `init_state.pos`。偏离 → FAIL「结束位置与位移终点不符」。

### 3.10 `sync`（含并行关系）

```json
{
  "with_dialogue": "after",
  "dialogue_span": [1.6, 4.5],
  "emotion": "cold_pressure",
  "relation": "reinforce",
  "parallel_with": ["ac_01HQ2M03"]
}
```

`parallel_with`：与本动作**同时发生**的动作 id 数组（双向声明，缺一边由程序补齐并标 INFO）。

## 四、"主动作"约束重做（修订 P1-4）

V1 规定「一镜内 `is_primary=1` 的行数必须 = 1」。**该约束废止**——它错误地禁止了合法群戏。

真实情况：
- 三人同场，A 摔纸、B 后仰、C 后退——三个都是"主叙事动作"，缺一个画面就假；
- 打戏里两个人同时对攻，都是主动作。

**V2 规则**：

| 规则 | 内容 | 级别 |
|---|---|---|
| R1 | 每镜至少 1 个 `is_primary=1`（`purpose=insert` 纯空镜可为 0） | FAIL |
| R2 | 主叙事焦点只允许 1 个——用 `focus_rank` 区分，而不是靠 is_primary 唯一 | WARN |
| R3 | 群戏中 `is_primary=1` 的动作，每个必须有独立的 `t_from/t_to` 区间（不得完全重叠） | WARN |
| R4 | 若同一角色在同一时间片有 2 个 `is_primary` 动作 → FAIL（一个人不能同时做两个大动作） | FAIL |
| R5 | `shot_blockings` 中 `power_level=high` 的角色，其 `is_primary` 动作数应 ≤ 其他人的和（主焦点不分散） | INFO |

`is_primary` 语义改为：**"这个动作承担叙事信息"**，而不是"唯一的动作"。真正的"单焦点"由 `focus_rank`（1=主焦点，2=次反应，3=背景）表达，与 `blocking-direction.md §4.2` 的"主焦点/次反应/背景行为"三级对齐。

`focus_rank` 作为 `sync` 的子键存在（`sync.focus_rank`），不新增列。

## 五、并行动作的时长计算（修订 P0-2 核心）

### 5.1 问题

V1 用 `Σ(t_to - t_from)` 判"动作塞不塞得下"。两人同时动作时，这个和翻倍，导致合法镜头被判 FAIL。

### 5.2 算法：并查集分组 + 组内取 max

```
输入：本镜所有动作 A = [a1..an]
1. 用 sync.parallel_with 建并查集，得到并行组 G1..Gk
   （未声明 parallel_with 的动作各自成组）
2. 每组占用时长 = max(t_to - t_from for a in group)
3. 镜内动作总占用 = Σ over groups(占用时长)
4. 动作可用时长 = story_duration
                   - 台词占用（中文 字/3.5，英文 词/3.8）
                   - 起势静默（默认 0.3s，T3 打戏 0.5s）
                   - 收势静默（默认 0.2s）
5. 若 总占用 > 可用时长 → FAIL「动作塞不下」
```

### 5.3 计算示例

镜时长 4.5s，台词 48 字符（英文 12 词 / 4.5s = 2.7 词/秒，合规），三个动作：

| 动作 | 区间 | 并行组 |
|---|---|---|
| A1 哈罗德前迈+摔纸 | 0.0–1.6 | G1 |
| A2 罗克珊后仰 | 1.2–2.0 | G1（与 A1 并行） |
| A3 凯森门口转头 | 2.0–3.0 | G2 |

```
G1 占用 = max(1.6, 0.8) = 1.6
G2 占用 = 1.0
总占用 = 2.6
台词占用 = 48 / 3.5（中文口径）；英文按 12 词 / 3.8 = 3.2s
可用 = 4.5 - 3.2(台词) - 0.3(起势) - 0.2(收势) = 0.8
2.6 > 0.8 → FAIL「动作塞不下：需 2.6s，可用 0.8s」
```

**这个判定是 V1 做不到的**：V1 只会把 1.6+0.8+1.0=3.4 与 4.5 比，得出"合规"的错误结论（因为它没扣台词时长）。

> 注：示例中"台词与动作重叠"是常态（边说边摔）。严格算法应看**时间片重叠**：`time_slices.kind='dialogue'` 的区间内允许动作并行。V2 采用简化版（台词全时长扣除），保守但不出错；精确版列入 D02 实施项。

## 六、动作时间线与镜头时间线（修订 P0-2 末项）

两条时间线必须分开存，且能互相校验：

| 时间线 | 载体 | 粒度 | 谁写 |
|---|---|---|---|
| **镜头时间线** | `story_shots.time_slices` | 片段时间片（`action`/`hold`/`dialogue`） | 创作层 |
| **动作时间线** | `shot_actions.t_from / t_to` | 每个动作的起止 | 创作层 |

**校验规则**：

| 规则 | 判据 | 级别 |
|---|---|---|
| T-1 | 每个动作区间必须被子时间片覆盖 | `[t_from,t_to]` 不被任何 `time_slices` 片段完整覆盖 → WARN |
| T-2 | 子时间片不得重叠 | 两片 `from/to` 交叉 → FAIL |
| T-3 | 子时间片总和 = `story_duration`（±0.1） | 不等 → FAIL |
| T-4 | 动作区间不得越出 `[0, story_duration]` | FAIL |
| T-5 | `kind='hold'` 片段内不得有动作（除 `speed.profile=hold` 的动作） | WARN |
| T-6 | `kind='dialogue'` 片段内若同时有 `contact` 动作，允许（边说边做），但要标 `sync.with_dialogue='during'` | INFO |

### 7.4 与下一镜的衔接校验

下一镜 `state_in` 由本 `state_out` 复制。校验项：

| 项 | 期望 | 若不符 |
|---|---|---|
| 哈罗德位置 | (0.26,0.66) | 偏差 >0.15 → `POSITION_JUMP` FAIL |
| 通知书状态 | placed / fx_table | 变回 held → `PROP_TELEPORT` FAIL |
| 罗克珊姿态 | sitting_upright | 变回 lying → `POSTURE_JUMP` FAIL（除非有 rise/lower 动作） |
| 凯森在场 | pos (0.10,0.28) | 消失 → `CHAR_POP` FAIL |

**这就是"能算出最终位置与道具状态"的完整链路**：坐标进、状态迁移进、逐条 apply 出、下一镜比对。

## 九、与运镜的严格区分（保留 V1，补充判定）

| 现象 | 归属 | 数据位置 |
|---|---|---|
| 人物从坐变站 | 人物动作 | `shot_actions(cog=rise)` |
| 人物从 A 走到 B | 人物动作 | `path` 坐标 |
| 画面整体平移 | 摄影机运动 | `story_shots.movement=truck_*` |
| 画面推近 | 摄影机运动 | `movement=dolly_in` |
| 人物大小变、背景不变 | 人物靠近（非变焦） | `path` 有 `to`，`movement=static` |
| 人物大小不变、背景压缩 | 光学变焦 | `movement=zoom_*` |
| 画面倾斜 | 摄影机滚转 | `cam_roll_deg ≠ 0`（**不是 dutch 枚举**） |
| 人物入画/出画 | 人物走位 | `path` + `in_frame` 变化 |

**三条硬规则**：同一件事不得两处都写；跟随类运镜必须有人物位移；人物位移必须有落点坐标。

## 十、不做的设计

| 不做 | 理由 |
|---|---|
| 不做骨骼/物理仿真 | 视频模型负责物理，分镜只给"物理意图" |
| 不做 FACS 全量编码 | FACS 归提示词层，分镜只到"情绪 + 强度 + 可见表情" |
| 不建招式库表 | 招式组合归打戏引擎 |
| 不强制 T1 写 `body_parts` | 小动作只写首尾态即可 |
