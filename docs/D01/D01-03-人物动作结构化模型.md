# D01-03 人物动作结构化模型（第三轮修订）

> 依赖：`D01-02`（ShotSpec 字段字典）、`D01-04`（坐标体系与状态可靠性）
> 本文回答：**动作怎么存才能被程序算；动作时间怎么算才不重复计时；动作时间线与镜头时间线什么关系。**
> 修订轮次：V3。V2 修好了"字段可计算"，但**时间计算仍是错的**（P1-01）：并行组取 max 再组间相加、把台词时长从动作可用时长中扣除。本轮把时间模型换成区间并集，并修正 V2 §5.3 的算术错误。

## 一、V1 的四个致命缺陷（评审 P0-2）

| # | V1 写法 | 为什么不能用 | V2 修正 |
|---|---|---|---|
| 1 | `path: {from:"床右侧 1.2m", to:"床右侧 0.6m"}` | 字符串无法计算位移距离、无法判穿模、无法与下一镜位置比对 | `path.from/to` 改为**坐标** `{x,y,z}`，原文字进 `label` |
| 2 | `result: {target_delta:"纸滑落一半垂在柜沿"}` | 无法推出道具最终状态，只能人读 | `result` 拆成 `char_delta` / `prop_delta` / `env_delta`，每项是**状态迁移**而非描述 |
| 3 | `end_state: {posture:"standing", hand:"双手空"}` | 没有位置，无法作为下一镜 `state_in` 的可计算来源 | `end_state` 必须含 `pos:{x,y}` + `props[]` 迁移结果 |
| 4 | 动作时长简单相加 | 两人同时动作会被算成两倍时长，误判"塞不下" | V2 引入并行组（组内 max、组间相加）——**仍错**：组间相加仍是跨人串行。V3 改为**按人分组、组内区间并集、跨人不相加**（§5） |

上一版虽写了"反应是独立行"，但没给 `trigger` 一个**可指向动作的 id**，导致"这个反应是谁引起的"仍无法查询。V2 修正。

## 二、三档粒度（保留 V1 设计）

| 档 | 必填字段 | 适用 | 依据 |
|---|---|---|---|
| **T1** `brief` | actor / type / init_state / trigger / result / end_state / t_from / t_to | 小动作：坐下、点头、递物 | `blocking-direction.md`「过渡招只需起点、受力点与状态继承」 |
| **T2** `standard` | T1 + path / speed / cog / contact / sync / body_parts | 有位移或接触 | 五段闭环 |
| **T3** `full` | 全 20 字段 + `force.chain` ≥8 环 | 关键重击 | `kinetic-chain-11.md` |

**自动判档**（程序判定，禁止模型自选）：

```
if (action_type=='combat' && is_key_blow)        → T3
else if (path.to || contact.target_id)           → T2
else                                             → T1
```

模型给 T1 但 `path.to` 非空 → 自动升 T2 + WARN；给 T3 但动作为"点头" → WARN「过度设计」。

### 3.1 `init_state`

```json
{
  "pos": { "x": 0.30, "y": 0.70, "z": 0 },
  "posture": "standing",
  "facing": "W",
  "cog": "stable",
  "hand": { "right": "持纸", "left": "空" },
  "gaze": "as_char_roxanne"
}
```

`pos` 必填（T1 起）——这是"可计算"的底线。若无法给出坐标，`pos=null` 且该动作降级为"不可计算动作"，不参与位置继承（`D01-04 §5` 会把它标为状态断裂）。

### 3.2 `trigger`（修订：可指向动作 id）

```json
{ "kind": "action",  "ref": "ac_01HQ2M01", "text": "对方把纸摔在柜上" }
{ "kind": "dialogue","ref": "line:2",      "text": "台词说完" }
{ "kind": "ambient", "ref": "sfx:monitor","text": "监护仪报警" }
{ "kind": "self",    "ref": "",            "text": "自主" }
```

`kind=action` 时 `ref` 必须是同镜或前镜的动作 id——**这是"反应动作关联触发动作"的实现**。校验：`ref` 不存在 → FAIL；`ref` 指向的动作 `t_to > 本动作 t_from` → WARN（因果倒置）。

### 3.3 `path`（修订：坐标形式）

```json
{
  "from": { "x": 0.30, "y": 0.70, "z": 0 },
  "to":   { "x": 0.26, "y": 0.66, "z": 0 },
  "via":  [ { "x": 0.28, "y": 0.68, "z": 0 } ],
  "move_type": "forward_step",
  "blocked_by": [],
  "distance_m": 0.62,
  "label": "床右侧 1.2m → 0.6m（病床与床头柜之间）"
}
```

| 字段 | 说明 |
|---|---|
| `from` / `to` | 归一化坐标（沿 `scene_states.coord_system.grid`），与 `shot_blockings.norm_x/y` 同源 |
| `via` | 必经点（绕开障碍） |
| `distance_m` | 由 `coord_system.active_area` 实际尺寸换算，**程序算，模型不填** |
| `label` | 人读文字（供提示词引用），**不参与计算** |
| `blocked_by` | 被绕开的 `fixtures.id` |

**穿模校验**：`from→to`（含 `via` 折线）与 `fixtures[].zone` 相交 → FAIL。这是"坐标化"换来的能力，V1 无法做。

### 3.4 `force`

```json
{
  "source": "右臂前摆，肩带动",
  "type": "downward_smash",
  "chain": ["蓄力（抬臂）", "肢体轨迹（下砸弧线）", "接触点（纸面拍柜）"]
}
```

T3 要求 `chain.length ≥ 8`（对应 11 环），T2 ≥ 3，T1 可空。

### 3.5 `speed`

```json
{ "profile": "sudden", "peak_at": 1.4, "avg_mps": 1.8 }
```

`profile ∈ constant / accelerate / decelerate / sudden / hold`。`sudden` 要求前置 `hold` 时间片（`D01-02 §10`），否则 WARN。

### 3.6 `body_parts`

```json
[
  { "part": "right_arm", "act": "抬至胸高后下压", "angle_from": 30, "angle_to": -15 },
  { "part": "left_shoulder", "act": "随之下沉" },
  { "part": "right_foot", "act": "前迈半步" }
]
```

`angle_from/to` 可选；有角度即可做"动作幅度"机检（越小越像静止）。

### 3.7 `contact`

```json
{
  "target_type": "prop",
  "target_id": "as_prop_notice",
  "point": "纸面中下部",
  "surface": "床头柜台面",
  "duration_ms": 120,
  "impulse": "medium"
}
```

`impulse ∈ light / medium / heavy`（替代模糊的"力度大/小"）。

### 3.8 `result`（修订：状态迁移，非描述）

```json
{
  "char_delta": {
    "as_char_harold": { "pos": [0.26,0.66], "hand": { "right": "空", "left": "空" }, "cog": "forward" }
  },
  "prop_delta": [
    { "prop_id": "as_prop_notice", "from": { "state": "held", "owner": "as_char_harold", "hand": "right" },
      "to":   { "state": "placed", "surface": "fx_table", "condition": "完好·一半垂在柜沿" } }
  ],
  "env_delta": []
}
```

| 键 | 内容 | 可计算性 |
|---|---|---|
| `char_delta` | 受影响角色的**新状态**（与 `end_state` 同结构） | 可直接覆盖 `state.chars[id]` |
| `prop_delta` | 道具的 `from → to` 状态迁移 | 可直接推 `state.props[id]`，且 `from` 必须等于当前状态（否则 FAIL「状态不一致」） |
| `env_delta` | 环境变化（门开、灯灭、时间推进） | 同样 from→to |

**这是"道具最终状态可计算"的实现**：`state_out.props = apply(result.prop_delta)`，不需要任何自然语言解析。

### 3.9 `end_state`

```json
{
  "pos": { "x": 0.26, "y": 0.66, "z": 0 },
  "posture": "standing",
  "facing": "W",
  "cog": "stable",
  "hand": { "right": "空", "left": "空" },
  "gaze": "as_char_roxanne"
}
```

**校验**：`end_state.pos` 必须等于 `path.to`（有位移时），容差 0.02；不位移则等于 `init_state.pos`。偏离 → FAIL「结束位置与位移终点不符」。

### 3.10 `sync`（含并行关系）

```json
{
  "with_dialogue": "after",
  "dialogue_span": [1.6, 4.5],
  "emotion": "cold_pressure",
  "relation": "reinforce",
  "parallel_with": ["ac_01HQ2M03"]
}
```

`parallel_with`：与本动作**同时发生**的动作 id 数组（双向声明，缺一边由程序补齐并标 INFO）。

## 四、"主动作"约束重做（修订 P1-4）

V1 规定「一镜内 `is_primary=1` 的行数必须 = 1」。**该约束废止**——它错误地禁止了合法群戏。

真实情况：
- 三人同场，A 摔纸、B 后仰、C 后退——三个都是"主叙事动作"，缺一个画面就假；
- 打戏里两个人同时对攻，都是主动作。

**V2 规则**：

| 规则 | 内容 | 级别 |
|---|---|---|
| R1 | 每镜至少 1 个 `is_primary=1`（`purpose=insert` 纯空镜可为 0） | FAIL |
| R2 | 主叙事焦点只允许 1 个——用 `focus_rank` 区分，而不是靠 is_primary 唯一 | WARN |
| R3 | 群戏中 `is_primary=1` 的动作，每个必须有独立的 `t_from/t_to` 区间（不得完全重叠） | WARN |
| R4 | 若同一角色在同一时间片有 2 个 `is_primary` 动作 → FAIL（一个人不能同时做两个大动作） | FAIL |
| R5 | `shot_blockings` 中 `power_level=high` 的角色，其 `is_primary` 动作数应 ≤ 其他人的和（主焦点不分散） | INFO |

`is_primary` 语义改为：**"这个动作承担叙事信息"**，而不是"唯一的动作"。真正的"单焦点"由 `focus_rank`（1=主焦点，2=次反应，3=背景）表达，与 `blocking-direction.md §4.2` 的"主焦点/次反应/背景行为"三级对齐。

`focus_rank` 作为 `sync` 的子键存在（`sync.focus_rank`），不新增列。

## 五、动作时间占用计算（P1-01 重写：区间模型）

### 5.1 V2 的算法错在哪

V2 的算法是「并查集分组 → 组内取 max → 组间相加 → 再从可用时长里扣台词」。它有三处错误，且**错的方向一致：把合法镜头判死**。

| # | 错误 | 具体 | 后果 |
|---|---|---|---|
| **E1** | 组间相加把不同人物的动作**串行化** | A1(哈罗德 1.6s) 与 A3(凯森 1.0s) 不同组 → 1.6+1.0=2.6 | 这是「人工时」，不是「镜头时长需求」。三个人同时动作，镜头仍然只占 1.6s |
| **E2** | 把台词时长从「可用动作时长」里扣除 | `可用 = D - 台词 - 起势 - 收势` | 等于**强制台词与动作串行**。但 V2 自己在 §6 的 T-6 写着「`kind='dialogue'` 片段内允许 `contact` 动作（边说边做）」，**两处规则互相矛盾** |
| **E3** | §5.3 示例本身算术不成立 | 同一句台词同时按「中文 48 字符」和「英文 12 词」两套口径算；`48/3.5 = 13.7s > 4.5s` 却称"合规"；`dialogue_span=[1.6,4.5]`（2.9s）与"占满 4.5s"也不一致 | 示例不可验算，等于没有验证 |

**E3 的直接后果**：V2 用这个算例得出「2.6 > 0.8 → FAIL」。下一节用同一组动作重算，结论是**合规**。也就是说 V2 会把一个完全正常的三人病房戏判为"动作塞不下"。

### 5.2 正确模型：区间并集，按人分组，不跨人相加

动作占用不是"把时长加起来"，而是"回答两个不同的问题"：

| 问题 | 量 | 用途 |
|---|---|---|
| Q1：这个镜头需要多长才能装下所有动作？ | `max over actors (unionLen(actor))` | 与 `story_duration` 比 |
| Q2：某个人的动作有没有互相打架？ | 同 actor 内区间重叠 + 部位冲突 | FAIL / WARN |

```js
function analyzeActionTime({ shot, actions }) {
  const D = shot.story_duration;
  const byActor = groupBy(actions, a => a.actor_id);
  const res = { perActor: {}, conflicts: [], warnings: [], requiredMin: 0 };

  for (const [actor, list] of byActor) {
    const iv = list.map(a => [a.t_from, a.t_to]).sort((x, y) => x[0] - y[0]);

    // ① 区间并集长度（重叠只算一次）
    let unionLen = 0, curS = null, curE = null;
    for (const [s, e] of iv) {
      if (curS === null) { curS = s; curE = e; }
      else if (s <= curE + EPS) { curE = Math.max(curE, e); }
      else { unionLen += curE - curS; curS = s; curE = e; }
    }
    if (curS !== null) unionLen += curE - curS;

    // ② 同 actor 重叠 → 检查部位冲突
    for (let i = 0; i < iv.length; i++) {
      for (let j = i + 1; j < iv.length; j++) {
        if (iv[j][0] >= iv[i][1] - EPS) continue;          // 不重叠
        const A = list[i], B = list[j];
        const shared = intersect(partsOf(A), partsOf(B));   // 共享独占组
        const declared = (A.sync?.parallel_with || []).includes(B.id)
                      || (B.sync?.parallel_with || []).includes(A.id);
        if (shared.length && !declared)
          res.conflicts.push({ code: 'ACTION_PART_CONFLICT', level: 'FAIL', actor,
                               a: A.id, b: B.id, parts: shared,
                               msg: `${actor} 在 ${iv[j][0]}–${iv[i][1]}s 同时用 ${shared.join('/')} 做两件事` });
        if (shared.length && declared)
          res.warnings.push({ code: 'ACTION_PART_SHARED', level: 'WARN', actor, a: A.id, b: B.id, parts: shared,
                              msg: '已声明并行，但同一部位同时承担两个动作，模型很可能演不出来' });
      }
    }

    res.perActor[actor] = { unionLen: round3(unionLen),
                            coverage: round3(unionLen / D),
                            count: list.length,
                            gaps: gapsOf(iv, D) };       // 静默间隙，供节奏判定
    res.requiredMin = Math.max(res.requiredMin, unionLen);
  }

  // ③ 越界（A-11）
  for (const a of actions) {
    if (a.t_from < -EPS || a.t_to > D + EPS || a.t_to <= a.t_from)
      res.conflicts.push({ code: 'ACTION_OUT_OF_RANGE', level: 'FAIL', id: a.id,
                           tFrom: a.t_from, tTo: a.t_to, dur: D });
  }

  // ④ 节奏：单人动作覆盖率过高 → 没有呼吸
  for (const [actor, v] of Object.entries(res.perActor)) {
    if (v.coverage > 0.9)
      res.warnings.push({ code: 'ACTION_NO_BREATH', level: 'WARN', actor, coverage: v.coverage,
                          msg: `${actor} 全镜 ${(v.coverage * 100).toFixed(0)}% 时间在动作，无起势/收势间隙` });
  }

  res.fits = res.requiredMin <= D + EPS;     // 由构造保证为真，保留作断言
  return res;
}
```

**关键判定**：`requiredMin = max(unionLen(actor))`。

- 不是 `Σ`——那是人工时；
- 也不是 `max(单动作时长)`——那是忽略了同一人先后两个动作要串行。

例：哈罗德先走位（0–1.6）再摔纸（1.6–2.8），他的 `unionLen = 2.8`（首尾相接会合并成一段）；而同镜凯森的 1.0s 动作**不增加**镜头需求，因为两人同时进行。

### 5.3 台词：不扣减，改判「口型冲突」

台词与动作**不是零和的**。一个人可以边说话边走路、边说话边摔东西。所以台词时长**不得**从动作可用时长中扣除。

台词只参与两件事：

| 事 | 判据 | 级别 |
|---|---|---|
| 语速 | 按 `sync.dialogue_span` 的实际时长算（**不是镜时长**），中文 字/秒、英文 词/秒 | V-09（`D01-02`） |
| 口型冲突 | 说这句话的人，在同一区间内有 `body_parts` 含 `head`/`face` 且 `power ≥ 8` 的动作 | WARN（A-14） |

```
语速 = 台词量 / span_duration
  中文：字符数（去标点）/ 3.5 字每秒为基准，> 4.5 判超速
  英文：词数（按空白切）/ 3.8 词每秒为基准，> 4.8 判超速
  停顿：句内 `，。！？` 每个计 0.15s 静默，从 span 中扣除后再算语速
```

**为什么必须用 `dialogue_span` 而不是镜时长**：一句 2.9s 的台词放在 4.5s 的镜里，剩余 1.6s 是动作/留白。V2 按 4.5s 算语速（2.67 词/秒"合规"），但真实口型要在 2.9s 内说完（4.14 词/秒，**超速**）。**用镜时长算语速会系统性低估语速，这是漏判而非误判，更危险。**

### 5.4 算例：同一组动作，V2 判 FAIL，V3 判合规

镜 `sh_11`，`story_duration = 4.5s`，三个动作：

| 动作 | 执行者 | 区间 | body_parts（独占组） |
|---|---|---|---|
| A1 前迈半步 + 摔纸 | 哈罗德 | 0.0–1.6 | `right_arm` / `right_foot` / `torso` |
| A2 后仰 | 罗克珊 | 1.2–2.0 | `torso` |
| A3 门口转头 | 凯森 | 2.0–3.0 | `head` |

台词：哈罗德说，英文 8 词，`dialogue_span = [1.6, 4.5]`。

```
按 actor 分组：
  哈罗德  union = [0,1.6]                        = 1.6     coverage 0.36
  罗克珊  union = [1.2,2.0]                      = 0.8     coverage 0.18
  凯森    union = [2.0,3.0]                      = 1.0     coverage 0.22

requiredMin = max(1.6, 0.8, 1.0) = 1.6 ≤ 4.5                                  ✓ 装得下
同 actor 内重叠：无（三人各一组）                                              ✓ 无部位冲突
越界：三个动作均在 [0,4.5] 内                                                  ✓
节奏：最高覆盖 0.36，无 ACTION_NO_BREATH                                      ✓

台词：8 词 / (2.9 − 0.15×1 停顿) = 8 / 2.75 = 2.91 词/秒 ≤ 4.8               ✓ 不超速
口型：哈罗德的台词在 1.6–4.5，他的动作在 0–1.6，不重叠                          ✓ 无口型冲突
```

**结论：合规。** V2 同一组数据判「FAIL：需 2.6s，可用 0.8s」，差在 E1（把凯森的 1.0s 加到哈罗德头上）与 E2（扣掉 3.2s 台词）。

**V2 算例的算术错误逐项核对**（保留以证明修正有效）：

| V2 写的 | 实际 |
|---|---|
| 台词 48 字符，英文 12 词 | 一段台词只有一种语言。中文 48 字 / 3.5 = 13.7s，**在 4.5s 镜里根本说不完**；英文 12 词则不是 48 字符 |
| 12 词 / 4.5s = 2.7 词/秒 | 若 `dialogue_span=[1.6,4.5]` 则分母是 2.9s → **4.14 词/秒**，超速 |
| 可用 = 4.5 − 3.2 − 0.3 − 0.2 = 0.8 | 算术本身对，但**这个减法不该做**（E2） |
| 总占用 = 1.6 + 1.0 = 2.6 | 把两人的动作相加（E1） |

### 5.5 因果依赖与并行的区别

| 关系 | 表达 | 校验 |
|---|---|---|
| **真并行**（同时发生） | `sync.parallel_with` 双向声明 | 必须双向；单边声明程序补齐并标 INFO（A-16） |
| **因果依赖**（B 因 A 而起） | `trigger = {kind:'action', ref:A.id}` | `B.t_from ≥ A.t_from`；`B.t_to < A.t_from` → FAIL 因果倒置（A-09） |
| **时间重叠但无因果** | 不声明 `parallel_with`，仅区间相交 | 不判冲突（不同人） |
| **同人不可能同时** | 区间重叠 + 共享 `body_parts` 独占组 + 未声明 | FAIL（A-12） |

**`parallel_with` 不是"允许重叠"的许可证**，它只是把"我们确实要同时"这件事显式化。两个人各自的动作本来就可以重叠，不需要声明；**声明只在同一人同一部位时才有判定意义**。

## 六、动作时间线与镜头时间线（修订 P0-2 末项）

两条时间线必须分开存，且能互相校验：

| 时间线 | 载体 | 粒度 | 谁写 |
|---|---|---|---|
| **镜头时间线** | `story_shots.time_slices` | 片段时间片（`action`/`hold`/`dialogue`） | 创作层 |
| **动作时间线** | `shot_actions.t_from / t_to` | 每个动作的起止 | 创作层 |

**校验规则**：

| 规则 | 判据 | 级别 |
|---|---|---|
| T-1 | 每个动作区间必须落在 `kind ∈ {action, dialogue}` 片段的**并集**内 | 不被并集覆盖 → WARN |
| T-2 | `time_slices` 自身不得重叠 | 两片 `from/to` 交叉 → FAIL |
| T-3 | 子时间片总和 = `story_duration`（±0.1）（同 A-15） | 不等 → FAIL |
| T-4 | 动作区间不得越出 `[0, story_duration]`（同 A-11） | FAIL |
| T-5 | `kind='hold'` 片段内不得有动作（除 `speed.profile=hold` 的动作） | WARN |
| T-6 | `kind='dialogue'` 片段内同时有 `contact` 动作，允许（边说边做），但要标 `sync.with_dialogue='during'` | INFO |
| T-7 | `time_slices` 只记**主导活动**，不与动作一一对应 | 不校验 |

**T-1 为什么从"被单个片段完整覆盖"改成"被并集覆盖"（P1-01 连带修正）**：

`time_slices` 是**互不重叠**的（T-2），而动作**可以重叠**（三人同时动作）。要求"每个动作区间被单个片段完整覆盖"在并行动作下无解——三个同时发生的动作不可能各自占一个互不重叠的片段。

正确理解：`time_slices` 描述"这一秒画面主要在干什么"（主导活动），`shot_actions` 描述"每个人在干什么"。两者是多对一关系，不是镜像。

例：`sh_11` 的 `time_slices` 可以是
```json
[{ "from":0.0, "to":1.6, "kind":"action",   "what":"哈罗德前迈摔纸" },
 { "from":1.6, "to":4.5, "kind":"dialogue", "what":"哈罗德施压" }]
```
而三个 `shot_actions` 的区间是 0–1.6 / 1.2–2.0 / 2.0–3.0。罗克珊的 1.2–2.0 跨了两个片段，凯森的 2.0–3.0 落在 dialogue 片段内——**都合法**，因为 A2/A3 不是主导活动。

## 八、校验规则（A-01 ～ A-18）

| 编号 | 规则 | 级别 |
|---|---|---|
| A-01 | 每镜 ≥1 个 `is_primary`（纯空镜可 0） | FAIL |
| A-02 | 同角色同时间片不得有 2 个 primary | FAIL |
| A-03 | 位移必有 `path.from/to` 坐标 | FAIL |
| A-04 | `end_state.pos` = `path.to`（容差 0.02） | FAIL |
| A-05 | 位移不穿 `fixtures.zone` | FAIL |
| A-06 | 位移终点与下镜 `state_in` 位置偏差 ≤0.15 | FAIL |
| A-07 | `contact.target_id` 存在且 category 匹配 | FAIL |
| A-08 | 有 `contact` 到角色时，该角色须有 `reaction` 动作 | WARN |
| A-09 | `trigger.kind=action` 的 `ref` 存在；`t_to(ref) < t_from(本)` → 因果倒置 | FAIL |
| A-10 | `result.prop_delta.from` = 当前道具状态 | FAIL |
| **A-11** | **动作区间越出 `[0, story_duration]` 或 `t_to ≤ t_from`** | FAIL |
| **A-12** | **同一 actor 两动作区间重叠，且共享 `body_parts` 独占组，未声明 `parallel_with`** | FAIL |
| **A-13** | **同一 actor 动作覆盖率 > 0.9（无起势/收势间隙）** | WARN |
| A-14 | 台词区间内该说话人有 `head`/`face` 且 `power ≥ 8` 的动作（口型冲突） | WARN |
| A-15 | `time_slices` 总和 = `story_duration`（±0.1） | FAIL |
| A-16 | `speed.profile=sudden` 且有前置 hold | WARN |
| A-17 | 档位与内容相符（§2 自动判档） | WARN |
| A-18 | `parallel_with` 双向一致 | INFO（程序补齐） |
| A-19 | T3 的 `force.chain` ≥8 | FAIL(T3) |

**A-11 的语义变化（P1-01）**：V2 的 A-11 是「动作总占用 ≤ 可用时长」，其中"总占用"是跨人相加、"可用时长"扣了台词。V3 拆成两条各管一件事：

- **A-11** 只管"动作是否在镜内"（纯区间包含，无算术）；
- **A-12** 只管"同一人是否在同时做两件互斥的事"（部位冲突）。

**没有"总占用 ≤ 可用"这条规则了**，因为它在数学上不成立——多人同时动作时"总占用"没有物理意义。真正约束时长的是 `story_duration` 本身与 `time_slices`（A-15），以及每个动作的区间合法性（A-11）。

**`body_parts` 独占组**（A-12 的判定依据）：

| 组 | 成员 | 说明 |
|---|---|---|
| 头面 | `head` `neck` `face` `gaze` | 同一时刻只能朝一个方向/做一个表情 |
| 躯干 | `torso` `hips` `spine` | 只能有一个重心姿态 |
| 右臂 | `right_shoulder` `right_arm` `right_hand` `right_fingers` | — |
| 左臂 | `left_shoulder` `left_arm` `left_hand` `left_fingers` | — |
| 下肢 | `left_leg` `left_foot` `right_leg` `right_foot` `cog` | 走位与站定互斥 |

判定：两动作的 `part` 落入**同一组**即视为共享；左右臂各自独立（左手操作手机 + 右手握手是合法的）。

## 九、与运镜的严格区分（保留 V1，补充判定）

| 现象 | 归属 | 数据位置 |
|---|---|---|
| 人物从坐变站 | 人物动作 | `shot_actions(cog=rise)` |
| 人物从 A 走到 B | 人物动作 | `path` 坐标 |
| 画面整体平移 | 摄影机运动 | `story_shots.movement=truck_*` |
| 画面推近 | 摄影机运动 | `movement=dolly_in` |
| 人物大小变、背景不变 | 人物靠近（非变焦） | `path` 有 `to`，`movement=static` |
| 人物大小不变、背景压缩 | 光学变焦 | `movement=zoom_*` |
| 画面倾斜 | 摄影机滚转 | `cam_roll_deg ≠ 0`（**不是 dutch 枚举**） |
| 人物入画/出画 | 人物走位 | `path` + `in_frame` 变化 |

**三条硬规则**：同一件事不得两处都写；跟随类运镜必须有人物位移；人物位移必须有落点坐标。

## 十、不做的设计

| 不做 | 理由 |
|---|---|
| 不做骨骼/物理仿真 | 视频模型负责物理，分镜只给"物理意图" |
| 不做 FACS 全量编码 | FACS 归提示词层，分镜只到"情绪 + 强度 + 可见表情" |
| 不建招式库表 | 招式组合归打戏引擎 |
| 不强制 T1 写 `body_parts` | 小动作只写首尾态即可 |
