### 2.1 列数（14 张表，全篇唯一口径）

统计方法：解析 `D01-05 §四` 每个 `CREATE TABLE` 块，取**以字段名开头的行**（排除 `UNIQUE`/`PRIMARY KEY`/`FOREIGN KEY`/`CHECK`/`CONSTRAINT` 与注释行），逐个数。

| `shot_states` | 8 | `§4.5` | 一致（`D01-02 §8` 曾写 7，本轮改 8） |
| `shot_assets` | **5** | `§4.6` | **V4 写 6 → 改 5** |

**两处错的根因不同**：

- `render_adaptations` 少算：历次按"DDL 里**带逗号**的行"计数，最后一行 `updated_at` 无逗号被漏掉（V3 漏 4、V4 漏 1，同一手法错三次）；

**⚠️ 这是 DDL 文本的设计值，不是 `PRAGMA table_info` 的实测值**（本轮禁 DDL）。实施建表后必须逐表 `PRAGMA` 复核（`D01-11 §九 #1`）。

## 三、每个 A 类里隐含的 B/C/D（诚实拆解）

| 编号 | 设计已满足的部分 | 仍隐含的缺口 | 类别 |
|---|---|---|---|
| P0-01 | 三处定义统一、七条规则、算例 D/E/F | 跨越检查 O(候选×动作)；真实 62 镜未跑；**算例仍全是手算** | B / D |
| P1-01 | 14 表列数逐列重数、口径统一 | 未 `PRAGMA` 实测；改 DDL 后无自动校验脚本 | **D** |
| P1-02 | 白名单 `bodyOf`、引用映射 contentHash、R-31~R-35 | `stripRef()` 未定义具体实现（依赖 `trigger_json` 的结构）；`canonicalStringify` 未实现 | **D** |
| P1-03 | DDL 双重约束 + CHECK + 三个算例 | SQLite 的 `CHECK` 在部分历史库不可加（需重建表）；历史 `order_no=0` 数据需清洗 | **D** |
| P1-04 | `DEFAULT NULL`、`posRel()`、五算例 | 已有库的 `norm_z` 列默认值仍是 0，**改列默认值需重建表**（SQLite 不支持 `ALTER COLUMN`） | **D / C** |
| 一致性 | 六类搜索已执行 | 搜索是文本层面，"语义一致但措辞不同"仍可能漏 | B |

**P1-04 的 D 类最实在**：SQLite 改列默认值必须 `CREATE TABLE new → INSERT SELECT → DROP → RENAME`。而 `shot_blockings` 是已有表（虽然 `norm_z` 是 D01 新增列）。若实施时用 `ALTER TABLE ADD COLUMN norm_z REAL DEFAULT 0`（沿用现有 `db.js` 的加法迁移风格），**这个 bug 会原样复现**，且不会报任何错。已在 `D01-11 §6.5 / §九 #4` 列为开工必检项。

## 五、结论

| 问题 | 回答 |
|---|---|
| V4 的跨文档冲突是否消除 | **是**（就本轮 5 项而言）。切点定义三处同义、列数一个口径、hash 无 id 泄漏、order_no 有库级约束、坐标缺失不再被默认值掩埋 |

> **D01 V5 是一份"定义已收紧、但完全未验证"的架构契约。**
