## v2.1.6（2026-11-05）· 分镜设计四缺口（镜内节拍 / 关系镜 / 距离常量 / 跨级机位）+ 接触关系不可删

**来源**：《你说我能抗，所以我该让》第一集 1-1 场真机连跑 6 段（0.7MP / steps10 / 二采4），镜01→镜05 逐帧复盘。**暴露的四个问题全部落在分镜设计层，不在词根层**——稿子词根干净、六段齐全，仍然崩。

**改动**

1. **`h3-shot-grammar.md §1.16 新增「单镜内的分节拍」**
   - 旧版只写了「首镜无时间戳、后续 `[Shot N] At` 递增」，**没规定一个连续镜头内分几个动作节拍怎么标**
   - 实测歧路：`[Shot 1] At 00:00.000 … [Shot 1] At 00:00.600 …` 同编号反复带时间戳 → 机检 `H2` FAIL，且模型把四段动作摊平，冲突时随机保一段
   - 新口径：**时间戳只属于切点，不属于节拍**。镜内节拍靠动作顺序连写；要控时用动作量代替秒数；视角真变才升 `[Shot N]`

2. **`§3.9 新增「关系镜：两个距离，一条连续的线」**
   - 旧版 §3.5 只说不许"中近景点名远处的人"，**没给"必须同框两个距离"的合法结构**
   - 两种结构：**切** / **一线连**（前景主体 + 实体道具线 + 远处主体，线两端同框）
   - 一线连三个必写项：近端固定点 / 线的路径 / 远端在对方手里（写"手指扣在绳身上"，不写"他抓着绳"）
   - 判据一句话：截一帧，能否同时看见"线在这一头"和"线在他手里"

3. **`§3.10 新增「距离常量表与距离感三要素」**
   - 距离必须像方位一样写成**跨镜常量**；改一处必须全片同步（本次只改镜01，镜04/05/06 的 12 m 全部作废，白跑三段）
   - **距离感不能靠"人小"表达**：靠垂直关系 + 够不到 + 道具线的形态
   - **0.7MP 人脸可辨距离上限 4–5 米**；超过就只写头发/肩线/手的动作。写"脸小 / 认不出来"会被理解成"这里不用画脸"，**模型直接删人**（三次复现）

4. **`§3.11 新增「跨数量级机位移动必须切」**
   - 与 §1.15 的"景别微变用运镜不切"配套：**厘米级同主体**用运镜；**米级换主体**（甲板→水面）必须切
   - 写成"镜头顺着手指压下去"→ 出片只保留一端，另一端整个消失

5. **`physics-realism.md §3.6 新增「接触关系不可删 —— 姿态可以妥协，接触不能」**
   - 三版废片实录：判定"手举太高"→ 写"不举过头顶"→ 仍举起 → 写"手臂全在水下" → **出片他独自漂在水里，一根绳都没有**
   - 根因：手举起来是物理结果（绳从船上斜垂，手必然朝绳的方向伸），压姿势压掉了"他抓着绳"这件事本身
   - 三铁律：接触点先写姿态后写 / 禁写"接触消失"类否定句 / 姿势不对改机位不改接触
   - 第 16 问扩为 17 问，新增"关键道具的接触点在本镜可见吗"

6. **`checklist.md` 扩到 77 项**
   - D 组 10→14：D31 单镜一个时间戳 / D32 关系镜二选一 / D33 距离常量 + 5 米脸线 / D34 米级落差用切
   - P 组 10→11：P11 关键道具接触点可见
   - `h3-shot-grammar.md` 一页速查补 4 条

**未改动**：词根层（否定根、元描述根）规则本身够用，本次翻车是**执行时没走清洗流程**，不是规则缺失；仅在 `h3-lexicon-cleanup` 使用上强调"解释性句子（这条绳是画面里唯一连贯的东西）属元描述根"。

## v2.1.5（2026-11-04）· 浸没语义优先律（F12）+ 判据口径修正

**现象**：第三次真机，段1 末帧仍是「双脚浸水、身体悬在船壁外、双手抓绳」的吊挂姿态，水到不了锁骨。

**根因（用户判定，三次验证）**：不是模型乱画，是**悬垂语义压过了浸没语义**。英文 `hang / dangle / suspend` 的默认语义就是「吊」，权重高于任何水位描写。前两次修的分别是「站姿」（v2.1）和「被吊出水面」（v2.2），第三次暴露的仍是同一个动词问题——写 `hangs in the sea` 也一样翻。

**改动**

1. **`physics-realism.md` §2.1 重写**：
   - 新增**第一铁律「浸没语义压倒一切」**，附三次真机对照表（v2.1 站水池 / v2.2 吊出水面 / v2.3 吊半空）
   - **禁词替换表**：`hangs in the sea` → `bobs half-submerged`；`stays suspended` → `stays half-submerged`；`legs hang free` → `legs trailing below the surface`；`feet dangling in open water` → `feet drifting beneath the water`
   - **四件套升级为含「浸没证据」**：① 没入线 ② **水正在包围身体**（`waves washing around his shoulders`）③ 腿在水下 ④ 衣物吸水。②是前几次漏掉的那件——只有抽象坐标，模型没有「被水包围」的凭据
   - **定义行锁**：人在水里的段，`<Subject N>` 定义行必须带 `half-submerged`（跨镜最高权重，锁一次胜过镜行写十遍）
   - 「致命陷阱」节升级为**两层**：第一层受力互斥（绳只保头），第二层动词语义（连 `hangs` 都不许用）
2. **`h3_finalcheck.py` 新增 F12「悬垂语义压过浸没语义」**：水镜里人物出现 `hang / dangle / suspend` → FAIL；绳、头发、布幡、烟等物件自动豁免。
3. **判据口径同步修正**（改判据比改稿子更重要）：
   - `FLOAT_RE` → `SUBMERGE_RE`：旧表把 `legs hang free / feet dangling` 当合格判据，等于把病灶写进了体检标准
   - `LEG_RE` / `IN_WATER_RE` 补 `below the surface` / `beneath the water` / `bobs` / `half-submerged`
   - **介质登记只认镜行**：摘要行是整段概括，常同句出现「甲板一人 + 水里一人」，按句归属会混成同一介质（L03 假阳性）
   - **视线落点不算站位**：`his eyes on the deck` 不等于他在甲板上
   - **`at the hull` 不算甲板**（水里的人就贴着船壳）；`bobs` 归水
4. **用例**：case30 升级为新写法（旧写法已属违规）；case31 新增 F12 反例镜并登记期望码，锁死这条规则。

**回归**：29 格式用例 100%；3 复检用例 + 模式库自检；文档自检全绿；三份 `physics-realism.md` md5 一致。

## v2.0.2（2026-11-01）· 五轮自测循环修复（4 个真 bug）

v2.0.1 之后按「测试 → 打分 → 修 → 再测」跑了五轮。前两轮只测脚本，第三轮换成测文档与真实用法后，分数从 8.5 掉到 7.5——**掉分那轮才是真实水位**，下面 4 个 bug 就是那时暴露的。

### 一、按文档做出来的清单.json，机检根本读不了（**最严重**）

`delivery.md §三/§四` 明确让用户"把带 `images` 数组的载荷 JSON 喂给 `h3_lint.py` 才查得到 H36"，但 §四 给的清单格式是**数组**，而 `load()` 只认**单个对象**。照文档操作的结果是直接报错：

```
读取失败：'list' object has no attribute 'get'
```

文档指的路，工具走不通——比没有这个功能更糟，因为用户会以为是自己写错了。

- **修法**：`load()` 支持三种载荷——单对象、**清单数组**、纯文本。清单数组会自动去读同目录下 `file` 指向的剥壳 `.txt`，自动取条目里的 `aspect`，多段自动拼接后走切分器。
- **报错可读**：清单里一条都读不到时，明确说"确认 `file` 指向的 .txt 与清单在同一目录，或条目里直接带 `prompt` 字段"，并列出缺失的文件名。
- **画幅优先级**：`--aspect` > 载荷 `aspect/aspect_ratio` > 正文里扫。
- **新增用例**：`case28`（清单正例）、`case29`（清单省图 → H36 FAIL）。

### 二、UTF-8 BOM 触发连锁假 FAIL

Windows 记事本 / Excel 导出的 UTF-8 默认带 BOM，BOM 会粘在首字段名前面变成 `\ufeffsubject_definitions`，六段式首字段认不出，于是 H1 报"缺字段"，接着 H20/H24/H27/H35 一起刷——**一份好稿看起来像废稿**。

- **修法**：`load()` 改用 `utf-8-sig` 读取，并对残留 BOM 兜底 `lstrip`。
- **新增用例**：`case25_bom_ok.md`（带 BOM 的正例，结果须与 case01 一致）。

### 三、全角冒号 `9：16` 与 `16x9` 写法漏检

中文输入法打出的全角冒号、以及口头常写的 `16x9`，原来都不匹配 `ASPECT_RE`。单个出现只是识别不到（退化成"未声明画幅"WARN），**但和半角写法混用时会被静默忽略，H14 混用检测直接失效**——段间换画幅这种必崩的错就漏过去了。

- **修法**：新增 `find_aspects()`，同时吃 `9:16` / `9：16` / `9 × 16` / `16x9`，统一归一化成半角 `a:b`；`x` 写法只认官方六档，避免把「3x3 网格」「1080x1920」误当画幅。
- **另加 WARN**：写法不规范时提示统一半角冒号（下游字符串匹配可能对不上），但不拦截。
- **新增用例**：`case26`（全角+半角混用 → FAIL）、`case27`（16x9 归一化 → 通过 + WARN）。

## v2.0.1（2026-11-01）· 审计修复（3 个真 bug）

v2.0.0 交付后做了一次全量审计，发现 3 个实打实的问题，全部修掉并补了回归用例。

### 一、切分把单段稿误判成两段（**最严重**）

`split_multi_segments` 把 `subject_definitions` 与 `integrated_multimodal_description` **都**当段起点。这两个是同一段里的不同字段，所以任何完整单段稿都会被切成 2 段——**剥壳后的 `.txt` 尤其必然中招**（它正是"字段名纯文本独占一行"，两行都命中）。后果是每段都缺字段，刷出一堆假 FAIL，用户会以为稿子废了。

- **修法**：先在两类字段里选出现次数多的那个当**唯一**锚点；两类都不超过 1 次 ⇒ 单段。
- **验证**：单段 `.md` / 载荷 `.json` / 剥壳 `.txt` 全部判 1 段；四段合稿仍正确判 4 段。
- **防复发**：新增 `case24_stripped_single_seg_ok.md`（剥壳单段稿，结果须与 case01 一致）。

### 二、H34 被当成"图槽越界"检查，实际它只查跨段类型

`H34` 只比对**同一 `Picture N` 在不同段是人还是场景**，从不看 `Picture M` 是否超出 `images` 长度。v2.0.0 删掉 `doctor` 后，把这个职责错挂到了 H34 上（`delivery.md` / `checklist` B14、I61 / `gates` P0-23 四处），会让人以为跑了 lint 就查过越界了。

- **修法**：`load()` 现在读取载荷的 `images` / `image_urls` / `media` / `refs` 数组；新增 **H36 图槽越界**——
  - 正文最大 `Picture N` > 数组长度 → **FAIL**；
  - 槽位是空值/空串 → **FAIL**（空槽等同省图，槽位照样前移）；
  - `Picture` 编号不连续 → WARN。
  - 输入是剥壳 `.txt`（无 `images`）时不触发，不打扰纯文生稿。
- **文档同步**：`delivery.md §三`、`checklist` B14/I61、`gates` P0-23、`diagnose.md §十` 维度 1、`pipeline.md` G5 全部改成「H36 查越界 / H34 查跨段类型」，并注明**必须喂载荷 JSON 才触发 H36**。
- **新增用例**：`case22`（4 张图对齐 → 未越界）、`case23`（引用 Picture 4 只给 2 张 → 越界 FAIL）。

### 三、版本串残留

- 全包 `H1–H35` → `H1–H36`，用例数 21 → 24。
